# Часть I. Гайд

## 1. Что это и как работает

TwitchCraft — клиентский мод для Minecraft 26.3 (Fabric). Он подключается к Twitch, VK Video Live и YouTube Live,
а также к сервисам донатов, и превращает **события** в **действия внутри игры**:

```
 Twitch: фоллов, подписка, ресаб, подарочные сабы, битсы, рейд,
         награда за баллы канала, сообщение/команда в чате        ─┐
 VK Video Live: чат и команды, запрос награды за баллы, фоллов     ├─►  TwitchCraft  ─►  действие в игре
 YouTube Live: чат, команды, членства, Super Chat / Super Sticker ─┤
 DonationAlerts: донат (мгновенно)                                 │
 DonatePay: донат (опрос раз в 20 с)                              ─┘
```

**Действие** — это набор из любых частей: сообщение в чат игры, большой заголовок на экране, текст над хотбаром,
всплывающее уведомление (тост), звук, ответ зрителю в чат платформы-источника (Twitch / VK / YouTube), список команд Minecraft (спавн мобов, эффекты, выдача
предметов, погода…) с паузами и повторами, таблица лута (случайный подарок), шанс срабатывания и кулдауны.

Главные принципы:

- **Основные настройки действий — в игре** (через Mod Menu или `/twitch config`) или в `config/twitchcraft.json`; OAuth-токены платформ хранятся отдельно. Файл уже содержит рабочие примеры «из коробки».
- **Каждая функция — модуль**, который можно выключить одной кнопкой (21 модуль).
- **Секреты не лежат в основном конфиге**: Twitch — Device Code Flow; VK — OAuth своего приложения; YouTube — OAuth Desktop + PKCE.
  Токены каждой платформы хранятся отдельно на твоём компьютере.
- **Twitch, VK и YouTube работают одновременно**: сопоставимые события используют общие действия, а специальные флаги и события каждой платформы остаются отдельными.
- Рассчитан на **одиночную игру** (команды выполняются на встроенном сервере с правами оператора, читы включать не нужно).
  На чужом сервере тоже работает, но команды уходят от твоего имени — нужен OP (см. [раздел 31](#31-игра-на-сервере)).
- Защита от спама: очередь, пауза (F8), лимит событий в минуту, кулдауны, чёрный список опасных команд.

## 2. Установка

Нужны: Minecraft Java Edition (официальный лаунчер или любой другой), 10 минут и доступ к интернету. Java отдельно
ставить **не нужно** — лаунчер использует свою.

1. **Fabric Loader.** Скачай установщик с <https://fabricmc.net/use/installer/>, запусти, выбери версию игры **26.3**,
   нажми *Install*. В лаунчере появится профиль **fabric-loader-26.3**.
2. **Fabric API** для 26.3 — файл `fabric-api-0.161.0+26.3.jar` (или новее для 26.3):
   <https://modrinth.com/mod/fabric-api/versions?g=26.3>.
3. **TwitchCraft** — файл **[`twitchcraft-1.11.0.jar`](https://github.com/cherdakmd/twitchcraft/releases/latest)**
   из вложения релиза на GitHub (в `release/` репозитория лежат jar 1.7.0 и 1.7.1; если нужной версии во вложениях нет —
   собери сам: `./gradlew build`, готовые файлы появятся в `build/libs`).
   Страница опубликованных версий: <https://github.com/cherdakmd/twitchcraft/releases>.
3а. **Аддон «Артефакты»** (по желанию) — `artifact-addon-1.0.0.jar` из вложения того же релиза или из `build/libs`.
   Это отдельный мод-файл: положи его в ту же папку `mods`. Без него TwitchCraft работает как обычно
   (просто не будет артефактов; `/twitch addons` скажет «аддоны не подключены»). Подробно — раздел 22г.
4. **Mod Menu** (по желанию, но очень удобно) — `modmenu-21.0.0.jar`:
   <https://modrinth.com/mod/modmenu/versions?g=26.3>. С ним в главном меню появляется кнопка **Моды**, а у TwitchCraft —
   кнопка **Настроить**. Без Mod Menu тот же экран открывается командой `/twitch config` из любого мира.
5. Положи все jar-файлы в папку `mods`:
   - Windows: `%APPDATA%\.minecraft\mods` (вставь путь в адресную строку Проводника);
   - macOS: `~/Library/Application Support/minecraft/mods`;
   - Linux: `~/.minecraft/mods`.
   Если папки `mods` нет — создай.
6. Запусти лаунчер, выбери профиль **fabric-loader-26.3**, нажми *Играть*.

Проверка: в главном меню → *Моды* (если есть Mod Menu) в списке есть **TwitchCraft 1.11.0** (и **Артефакты**, если поставил аддон).
Или зайди в любой мир и набери `/twitch` — появится справка, а `/twitch addons` покажет подключённые аддоны.

> **Обновление с прошлых версий**: просто замени jar. Конфиг дополнится новыми разделами сам, твои награды и команды
> останутся. **После обновления на 1.7.0** один раз сделай `/twitch logout` → `/twitch login` — без этого не будет прав на клипы
> и метки стрима (`clips:edit`, `channel:manage:broadcast`). Если обновляешься с 1.0.0 — тем более, чтобы выдать моду права
> на чат и управление наградами. Аддон «Артефакты» — отдельный файл: при обновлении мода обнови и его jar (или просто убери —
> мод без него работает). Настройки аддона (`config/twitchcraft-artifacts.json`) при этом сохраняются.

## 3. Регистрация приложения в Twitch

Twitch требует, чтобы у каждой программы, читающей события канала, был свой **Client ID**. Это бесплатно и делается один раз.

1. Открой <https://dev.twitch.tv/console/apps> и войди под аккаунтом **владельца канала** (dedworkshop).
   Twitch попросит включить двухфакторную аутентификацию, если она ещё не включена.
2. Нажми **Register Your Application** и заполни форму:

   | Поле | Что ввести |
   |---|---|
   | Name | любое, например `TwitchCraft dedworkshop` (название должно быть уникальным на Twitch) |
   | OAuth Redirect URLs | `http://localhost` |
   | Category | `Game Integration` |
   | Client Type | **Public** — обязательно! С типом Confidential вход без секрета не работает |

3. Нажми **Create**, затем **Manage** у созданного приложения. Скопируй **Client ID** (строка из ~30 букв и цифр).
   **Client Secret не нужен** — не создавай его, мод его не спрашивает.

Client ID — не секрет, его можно показывать. Он лишь говорит Twitch, какая программа просит доступ.

## 4. Первый вход и подключение

### Способ 1 — экран настроек (Mod Menu)

Главное меню → *Моды* → *TwitchCraft* → *Настроить* → **Общие настройки** → поле *Client ID* → вставь → **Сохранить** →
назад → кнопка **Войти в Twitch**. Прямо на экране появятся код из 8 символов и кнопки
**Открыть twitch.tv/activate** и **Скопировать код**. Входить в мир не обязательно.

### Способ 2 — команды в чате игры

Зайди в любой мир (можно творческий тестовый) и введи:

```
/twitch setup ВСТАВЬ_СЮДА_CLIENT_ID
/twitch login
```

### Что происходит дальше (оба способа)

1. В браузере открой `https://www.twitch.tv/activate` (ссылка кликабельна в чате). Убедись, что вошёл как **владелец канала**:
   мод получает события именно того канала, чей аккаунт подтвердит код.
2. Введи код (клик по коду в чате копирует его), нажми **Активировать**.
3. Подтверди права: награды за баллы, подписки, битсы, фолловеры, чтение и отправка чата, управление наградами.
4. Вернись в игру. Через пару секунд: `[Twitch] Подключено к Twitch как dedworkshop — подписок: 8/8 (+чат)`.

С этого момента мод подключается **автоматически при каждом входе в мир** (`autoConnect`), токены обновляет сам,
логиниться повторно не нужно. Состояние в любой момент: `/twitch status`.

> **Награды за баллы можно не создавать руками.** Введи `/twitch rewards sync` (или кнопка *Создать награды на Twitch*) —
> мод создаст на канале все награды из конфига с ценой и описанием. Созданные модом награды он умеет **подтверждать** и
> **возвращать за них баллы**, если событие не выполнилось. Награды за баллы, подписки и битсы доступны только
> аффилиатам и партнёрам; фолловы, рейды и чат работают у всех.

## 5. Проверка без зрителей

Все команды `/twitch test …` имитируют событие **локально**: Twitch не трогается, кулдауны не ставятся, в статистику
и цели не попадают.

```
/twitch test follow                 новый фолловер → подарок из таблицы лута
/twitch test sub                    подписка Tier 1
/twitch test resub 12               ресаб на 12 месяцев → сработает порог «12»
/twitch test gift 5                 5 подарочных подписок
/twitch test cheer 1000             1000 битсов → гром и молния
/twitch test raid 50                рейд на 50 зрителей → «большой рейд»
/twitch test reward Пакость         награда за баллы «Пакость» → случайное ☠ событие из ценника
/twitch test reward Подарок         награда «Подарок» → случайное ★ событие
/twitch test chat !zombie           сообщение в чате Twitch (от имени стримера)
/twitch vk test chat !zombie        то же, но «как будто из чата VK Video Live»
/twitch vk test reward Пакость      запрос награды «как будто с VK»
/twitch test goal Фолловеры         награда за достижение цели
/twitch test donation 500 Привет!   донат 500 ₽ с сообщением
/twitch rewards                     список наград — клик по названию = тест
/twitch replay   (или F9)           повторить последнее событие
```

В экране настроек у каждой награды, события, порога, чат-команды и цели есть кнопка **Тест** (нужно быть в мире).
Чтобы увидеть, что сделала команда Minecraft (например, ответ `give`), временно включи `showCommandOutput` (*Общие
настройки → Показывать вывод команд*).

## 6. Первая своя награда за баллы

Из коробки наград две — **«Пакость»** и **«Подарок»** по 250 баллов: каждая запускает **случайное** событие из ценника донатов
(☠ одно из 25 или ★ одно из 25). Их достаточно для старта: `/twitch rewards sync` (Twitch) и `/twitch vk rewards sync` (VK) создадут их на каналах.
Подробнее — [раздел 17](#17-награды-за-баллы-канала). А здесь сделаем свою награду с фиксированным эффектом.

Сделаем награду «Наковальня» — на голову стримеру падает наковальня.

**Через экран настроек:** `/twitch config` → **Награды за баллы** → **Добавить** → имя `Наковальня` → откроется редактор:

| Поле | Значение |
|---|---|
| Сообщение | `&c{user} &7уронил на тебя наковальню!` |
| Заголовок | `&cБУМ!` |
| Звук | `minecraft:block.anvil.land` |
| Команды | `setblock ~ ~3 ~ minecraft:anvil` |
| Стоимость | `400` |
| Описание | `Наковальня падает на стримера` |
| Кулдаун | `30` |

**Тест** — проверить, **Сохранить** — записать. Потом `/twitch rewards sync` — награда появится на Twitch.

**Через JSON** (`config/twitchcraft.json`, раздел `rewards`):

```json
"Наковальня": {
  "message": "&c{user} &7уронил на тебя наковальню!",
  "title": "&cБУМ!",
  "sound": "minecraft:block.anvil.land",
  "commands": ["setblock ~ ~3 ~ minecraft:anvil"],
  "cost": 400,
  "prompt": "Наковальня падает на стримера",
  "cooldown": 30
}
```

Сохрани файл → `/twitch reload` → `/twitch test reward Наковальня` → `/twitch rewards sync`.

Правила: ключ в `rewards` = **название награды на Twitch / VK Video Live** (регистр не важен). Если ты создаёшь награды сам в панели
Twitch или в студии VK — называй их так же. Запись `"*"` срабатывает для любой награды, у которой нет своего пункта.

## 7. Первая чат-команда

Сделаем `!tnt` — только для подписчиков, раз в 2 минуты, с ответом в чат.

`/twitch config` → **Чат-команды** → **Добавить** → имя `tnt`:

| Поле | Значение |
|---|---|
| Сообщение | `&c{user} &7заложил TNT!` |
| Команды | `summon minecraft:tnt ~ ~ ~2` |
| Права | `subscriber` |
| Кулдаун | `120` |
| Алиасы | `тнт, boom` |
| Ответ в чат | `{user}, TNT заложен. Беги, стример!` |

Зритель пишет в чат Twitch `!tnt` (или `!тнт`, `!boom`) → мод проверяет права и кулдаун → выполняет. Если зритель не подписчик,
мод ответит ему `@ник, эта команда только для подписчиков` (текст настраивается, см. [раздел 20](#20-ответы-в-чат-twitch)).
Проверить самому: `/twitch test chat !tnt` (тест идёт от имени стримера, права проходят всегда).

## 8. Подключаем донаты

Донаты работают **независимо от Twitch**. Можно подключить один сервис или оба.

### DonationAlerts (мгновенно, 3 минуты)

1. <https://www.donationalerts.com/application/clients> (под аккаунтом стримера) → **Создать приложение**:
   название любое, **Redirect URI** ровно `http://localhost:8631/da`.
2. Скопируй **Client ID** приложения (число). Секрет не нужен.
3. В игре: `/twitch donations da client <Client ID>` (или экран **Донаты** → поле *Client ID* → **Сохранить**).
4. `/twitch donations da login` (или кнопка **Войти в DonationAlerts**) → в браузере **Разрешить** → страница скажет «Готово!»,
   в игре появится `DonationAlerts: вход выполнен как …`, и мод подключится сам.

### DonatePay (опрос раз в 20 секунд)

1. <https://donatepay.ru> → **Настройки → API** → скопируй **API-ключ** (это секрет — не показывай на стриме).
2. В игре: `/twitch donations dp key <ключ>` (или экран **Донаты** → поле *API-ключ* → **Применить ключ**).
   Мод проверит ключ, покажет имя аккаунта, запомнит последний уже существующий донат и дальше будет забирать только новые.

### Проверка

`/twitch test donation 250 Спасибо за стрим!` → сработает порог **250 ₽** («☠ Молния»), `/twitch test donation 45` → **40 ₽** («★ Перекус»).
`/twitch donations prices` — весь ценник (25 пакостей и 25 подарков), `/twitch donations` — статус обоих сервисов.
В оверлее появятся метки `DA●` / `DP●`. Подробности, валюты, свои пороги — в [разделе 22](#22-донаты-donationalerts-и-donatepay).

**Сбор на что-то конкретное** (микрофон, новый ПК, благотворительность)? Вверху экрана уже висит полоса «Сбор на стрим: 0 / 5 000 ₽» —
как у босса. Донаты заполняют её сами. Переименовать и задать цель: экран **Сборы средств (боссбар)** или
`/twitch fund target Сбор 15000`. Не нужна — `/twitch fund hide Сбор`. Подробности — [раздел 21а](#21а-сборы-средств--полоса-боссбар).

## 8а. Подключаем VK Video Live

Стримишь на **live.vkvideo.ru** (параллельно с Twitch или вместо него)? Мод подхватит чат VK, `!команды`, запросы наград за баллы и
фолловы — через те же действия, что и Twitch. Нужно своё приложение VK Video Live (бесплатно, 3 минуты).

1. Открой <https://dev.live.vkvideo.ru/apps> (вход через VK ID тем же аккаунтом, что стримит) → **Создать приложение**.
   Название любое, **Redirect URI** ровно `http://localhost:8638/vk`. Сохрани → скопируй **ID приложения** и **секретный ключ**.
2. В игре: `/twitch vk app <ID> <секрет>` (или экран **VK Video Live** → поля *ID приложения* и *Секрет* → **Сохранить**).
   Секрет уходит в отдельный файл `config/twitchcraft-vk.json`.
3. `/twitch vk login` (или кнопка **Войти в VK Video Live**) → в браузере **Разрешить** (права: отправка в чат, баллы канала, награды,
   запросы наград) → страница «Готово!» → в игре `VK Video Live: вход выполнен как …` и мод подключится сам.
   Если браузер не открыл localhost (например, другой компьютер) — скопируй из адресной строки значение `code=…` и введи `/twitch vk code <код>`.
4. `/twitch vk rewards sync` (или кнопка **Создать награды на VK**) — создаст на канале награды из конфига («Пакость», «Подарок»…).
   Для этого в студии VK Video Live должны быть **включены баллы канала**.
5. Проверка: `/twitch vk` — статус (`подключено к dedworkshop [чат ● награды ● журнал ●]`), в оверлее метка `VK●`.
   `/twitch vk test chat привет`, `/twitch vk test follow`, `/twitch vk test reward Пакость` — локальные тесты.
   Напиши что-нибудь в чат своего канала на сайте — сообщение появится в игре с префиксом `[VK]`.

Канал по умолчанию — `https://live.vkvideo.ru/dedworkshop` (`vk.channelUrl`); можно указать другой: `/twitch vk channel <ссылка>`.
Если поле пустое, мод подключается к собственному каналу вошедшего аккаунта. Все тонкости — [раздел 22а](#22а-vk-video-live).

## 8б. Подключаем YouTube Live

Для YouTube нужен Google OAuth-клиент типа **Desktop app** и включённый YouTube Data API v3. У YouTube нет аналога Twitch Client ID/секретного ключа: укажи только публичный OAuth Client ID, секреты и токены в основной конфиг не копируй.

1. В Google Cloud Console создай проект, включи **YouTube Data API v3**, настрой экран согласия OAuth и создай OAuth Client ID типа **Desktop app**.
2. Открой `/twitch config` → **YouTube Live**: вставь Client ID (или `/twitch youtube client <Client ID>`), проверь callback `http://localhost:8640` и включи модуль `youtubeLive`. Порт можно изменить в настройках; это loopback URL без пути.
3. Выполни `/twitch youtube login` (или нажми **Войти в YouTube Live**). Откроется браузер; войди в аккаунт, который владеет каналом, подтверди права и дождись callback. Вход — Authorization Code + PKCE с проверкой `state`; если localhost callback не сработал, передай полный URL: `/twitch youtube code <URL>`.
4. Мод проверит канал и найдёт активную трансляцию. Проверяй состояние `/twitch youtube` и `/twitch youtube info` (эфир, зрители, квота, следующая попытка); вручную переподключить — `/twitch youtube connect`, отключить — `/twitch youtube disconnect`. Автоподключение выполняется при следующем входе в мир. Если эфира нет, поиск повторяется каждые 5 минут и почти не тратит квоту.
5. Проверь флаги YouTube на экране настроек: `showChat`, `chatCommands`, `paidMessages`, `memberships`, `replies`, `trackViewers`, `quotaGuard`, `control`, `showModeration`. Тесты: `/twitch youtube test chat !zombie`, `member`, `milestone`, `gift`, `superchat`, `sticker`, `funding`, `ban`.
6. Дневная квота YouTube Data API (10 000 единиц на проект) видна в `/twitch youtube info`; порог — `youtube.quotaBudget` (по умолчанию 9 000). Когда порог исчерпан, мод сам останавливает опрос и возобновляет его после сброса Google.

Access/refresh tokens и профиль сохраняются отдельно в `config/twitchcraft-youtube.json`; файл секретный. Client ID остаётся в `config/twitchcraft.json`. Выход с отзывом токена: `/twitch youtube logout`. Подробности: [раздел 22б](#22б-youtube-live).

## 9. Чек-лист перед стримом

1. Зайди в мир, дождись `Подключено к Twitch как …` (или проверь `/twitch status`: EventSub — подключено, подписок N/N).
2. Если донаты настроены — в `/twitch status` строки DonationAlerts / DonatePay — «подключено».
   Для VK Video Live проверь `/twitch vk` и метку `VK●`; для YouTube — `/twitch youtube`, активный live chat и метку `YT●`.
   Если платформа отключена вручную, выполни `/twitch vk connect` или `/twitch youtube connect`.
3. `F7` — оверлей включён и стоит в нужном углу (не перекрывает важное; угол меняется в *Общие настройки → Оверлей*).
4. Если менял конфиг руками — `/twitch reload` и посмотри, нет ли предупреждений.
5. Если добавил награды — `/twitch rewards sync` (Twitch) и `/twitch vk rewards sync` (VK), затем проверь в панели, что они включены.
6. `/twitch stats reset` — обнулить статистику прошлой сессии (цели сбрасываются сами, если мод не запускался 12 часов).
7. Прогони пару `/twitch test …`, чтобы убедиться, что звук/заголовки видны в захвате OBS (оверлей и тосты рисуются внутри игры —
   захват окна игры их покажет).
8. Проверь, что в чате Twitch нет второго мода/бота, который делает то же самое (например, Take Your Stream Chat тоже показывает чат —
   тогда `/twitch chat off`, чтобы не дублировать).
9. `/twitch game` — строка «Стрим: в эфире …» появится через минуту после начала эфира; права на клипы и метки — «есть»
   (если «нет права» — `/twitch logout` и `/twitch login` заново, см. раздел 22в). `/twitch game reset` — обнулить счётчик смертей за стрим.

## 10. Во время стрима

| Ситуация | Что делать |
|---|---|
| Нужно спокойно поговорить / босс / сложный момент | **F8** — пауза. События копятся в очереди (`/twitch queue`) и выполнятся после второго нажатия F8 |
| Зрители устроили спам наградами | Включён лимит `maxEventsPerMinute` (30) — лишнее встаёт в очередь. Можно `/twitch queue clear` — очередь очистится, баллы вернутся |
| Пропустил эффект и хочешь показать ещё раз | **F9** — повтор последнего события (как тест: без баллов и целей) |
| Оверлей мешает | **F7** |
| Случилось что-то эпичное | **F10** — клип и метка стрима; ссылка на клип придёт в чат игры и зрителям через ~15 с. Смерть, донат от 50 ₽ и босс делают это сами |
| Бот напоминает о ценнике слишком часто / редко | *Таймеры чата* → интервал и минимум сообщений; `/twitch timers off ценник` — выключить до конца стрима |
| Зритель скинул деньги мимо DonationAlerts (на карту, наличными) | `/twitch fund add Сбор 500 Вася` — полоса сбора пополнится, как от доната |
| Полоса сбора мешает (или перекрывает босса) | `/twitch fund hide Сбор` (вернуть — `show`); отступ сверху — в настройках сборов |
| Кто-то злоупотребляет командой | Добавь логин в *Игнорировать логины* (`ignoredUsers`) или выключи команду (переключатель *Включено* в редакторе) |
| Хочешь выключить одну функцию на время | *Модули* или `/twitch module <id> off` — применяется сразу |
| Надо выйти в меню | Можно: при `queueWhenNotInWorld` события подождут в очереди, пока ты не вернёшься в мир |
| Связь с Twitch пропала | Мод переподключается сам (1, 2, 4… до 60 с), в чате — `Связь с Twitch потеряна` → `Подключено`. Оверлей показывает `○ оффлайн` |

Все эффекты, кроме команд Minecraft, — только на твоём экране (заголовки, тосты, звуки). Зрители видят их через захват игры.

## 11. После стрима

- `/twitch stats` — сводка сессии: фолловы, сабы, битсы, рейды, награды, чат-команды, цели, донаты.
- `/twitch history 30` — последние 30 событий со статусами (выполнено / кулдаун / пропущено…).
- `logs/twitchcraft-events.log` — журнал всех событий за всё время (кто, что, когда, статус).
- `/twitch goals` — прогресс целей. Если хочешь начать следующий стрим с нуля — `/twitch goals reset`.

## 12. Модули

Каждая функция мода — модуль. **Выключенный модуль** не создаёт подписок на события Twitch, не обрабатывает свои события и не
показывает свои элементы интерфейса. Переключать: экран **Модули**, команда `/twitch module <id> on|off|toggle`, раздел
`"modules"` конфига. Список с состоянием: `/twitch modules`. Переключение применяется сразу; если изменился набор событий
(группы «События» и «Чат»), мод сам переподключается к Twitch.

## 13. События Twitch и выбор действия

### Типы событий

| Событие | Откуда | `{amount}` | `{message}` | `{tier}` | Действие в конфиге |
|---|---|---|---|---|---|
| Фоллов | `channel.follow` | 0 | — | — | `follow` |
| Подписка (новая, не подарок) | `channel.subscribe` | 1 | — | 1 / 2 / 3 / Prime | `subscribeByTier` → иначе `subscribe` |
| Ресаб (продление с сообщением) | `channel.subscription.message` | месяцев подряд | текст зрителя | уровень | `resubTiers` → `resubByTier` → иначе `resub` |
| Подарочные подписки | `channel.subscription.gift` | сколько подарено | — | уровень | `giftSubTiers` → `giftSubByTier` → иначе `giftSub` |
| Битсы | `channel.cheer` | битсов | текст зрителя | — | `cheer` (пороги) |
| Рейд | `channel.raid` | зрителей | — | — | `raidTiers` → иначе `raid` |
| Награда за баллы | `…redemption.add` | стоимость в баллах | ввод зрителя | — | `rewards` (по названию) → `"*"` |
| Сообщение чата | `channel.chat.message` | битсы в сообщении (если есть) | текст | — | показ в чате; распознавание команды |
| Чат-команда | из сообщения чата | — | аргументы после имени команды | — | `chatCommands` |
| Цель достигнута | внутреннее | порог цели | номер достижения | — | `goals[].action` |
| Сбор закрыт | внутреннее | цель сбора | какой раз закрыт | код валюты | `fundraisers[].action` |
| Донат | DonationAlerts / DonatePay | сумма (целое, в основной валюте) | текст донатера | код валюты | `donationAlertsTiers` / `donatePayTiers` → иначе `donationTiers` |

В этой таблице перечислены Twitch и общие игровые/донатные события. Сопоставление VK описано в [§22а](#22а-vk-video-live), YouTube — в
[§22б](#22б-youtube-live); событие несёт отдельную платформу, но совместимые типы проходят через тот же конвейер действий.

Анонимные подарки и битсы приходят от зрителя «Аноним» (без логина — персональные кулдауны к ним не применяются).
Подарочные подписки **не** создают отдельных событий «подписка» для каждого получателя — только одно событие «подарил N».

### Пороги («от N»)

Таблицы `cheer`, `resubTiers`, `giftSubTiers`, `raidTiers`, `donationTiers` (и сервисные) устроены одинаково:
ключ — **минимальное значение**, строкой (`"100"`), значение — действие. Выбирается **самый большой порог, не превышающий**
`{amount}`:

```
cheer: { "1": A, "100": B, "1000": C }
   37 битс → A      100 битс → B      999 битс → B      1500 битс → C
```

- Для ресаба, подарков и рейда, если ни один порог не подошёл (например, таблица пуста или все ключи больше `{amount}`),
  срабатывает **базовое** действие `resub` / `giftSub` / `raid`.
- Для битсов и донатов базового действия нет: если сумма меньше самого маленького ключа — ничего не происходит.
- Ключи, которые не являются числом, игнорируются.
- В экране настроек пороги правятся кнопкой **Пороги (N)** рядом с событием.

### Уровни подписки (1/2/3/Prime)

Подписки приходят с уровнем (`{tier}` — `1`, `2`, `3` или `Prime`). Чтобы на разные уровни раздавать разные подарки,
есть таблицы `subscribeByTier` (новая подписка), `resubByTier` (ресаб) и `giftSubByTier` (подарки): ключ — уровень,
значение — действие. Порядок выбора:

- **Новая подписка**: действие из `subscribeByTier` для её уровня, иначе базовое `subscribe`.
- **Ресаб и подарки**: сначала пороги по количеству (`resubTiers` — месяцы, `giftSubTiers` — штук); если ни один
  не подошёл — действие уровня из `resubByTier` / `giftSubByTier`, иначе базовое `resub` / `giftSub`.

Ключи не различают регистр и понимают сырые значения Twitch: `"2"`, `"Tier 2"` и `"2000"` — одно и то же;
`"prime"` и `"Prime"` — тоже. Несуществующих уровней (`"4"`) быть не может — конфиг предупредит.
В экране настроек: *События Twitch* → **Уровни (N)** рядом с подпиской, ресабом и подарками; проверить без зрителей —
`/twitch test sub 3`, `/twitch test gift 5 3`. Подписки с VK Video Live всегда приходят уровнем 1.

### Что происходит с событием (порядок)

1. Модуль события включён? Нет — событие пропускается (тесты — исключение).
2. Сообщения чата обрабатываются отдельно (показ + распознавание команды), см. разделы 18–19.
3. Ты не в мире? → в очередь (`queueWhenNotInWorld: true`, в чате — `В очередь (ты не в мире)`) или пропуск с возвратом баллов (`Пропущено (игрок не в мире)`).
4. Пауза (F8)? → в очередь. Превышен `maxEventsPerMinute`? → в очередь.
5. В чат игры пишется строка `X зафолловил(а) канал` и т.п. (`showEventsInChat`).
6. Ищется действие (таблица выше). Нет действия или оно выключено — событие всё равно засчитывается в цели и статистику.
7. Для чат-команд — проверка **прав**; нет прав → ответ в чат платформы-источника (если разрешён), конец.
8. **Кулдаун** (общий и персональный) → ответ в чат источника, возврат баллов за поддерживаемую награду, конец.
9. **Шанс** (`chance` < 100) → если не повезло: `failMessage`, кулдаун ставится, баллы считаются потраченными (лотерея честная).
10. Выполнение: сообщение → заголовок/подзаголовок → текст над хотбаром → тост → звук → ответ в чат платформы-источника → команды
    (с паузами `delay` и повторами) → выпавшая запись таблицы лута (её эффекты и команды) → подтверждение награды на Twitch.
11. Событие засчитывается в цели и сборы средств; достигнутые цели и закрытые сборы обрабатываются как отдельные события
    «цель» / «сбор закрыт» (у них свои действия).

## 14. Действие — все поля

Действие — универсальный блок настроек. Один и тот же формат используется для наград, событий, порогов, чат-команд, целей,
донатов и записей таблицы лута. Любое поле можно опустить; пустое действие `{}` = ничего не делать.

```json
{
  "enabled": true,
  "message": "&c{user} &7натравил на тебя зомби!",
  "title": "&cЗОМБИ!",  "subtitle": "&fот {user}",
  "actionbar": "&7Беги!",
  "toast": "&dНаграда",  "toastText": "{reward} от {user}",
  "sound": "minecraft:entity.zombie.ambient",  "volume": 1.0,  "pitch": 1.0,
  "commands": ["summon minecraft:zombie ~2 ~ ~2", "delay 20", "summon minecraft:zombie ~-2 ~ ~2"],
  "randomOne": false,
  "repeat": "",  "repeatPer": 1,  "maxRepeat": 10,  "repeatDelay": 5,
  "chance": 100,  "failMessage": "",
  "cooldown": 0,  "userCooldown": 0,
  "reply": "{user}, зомби уже бегут!",
  "permission": "everyone",  "aliases": [],
  "cost": 0,  "prompt": "",  "input": false,  "color": "",
  "loot": [],  "name": "",  "weight": 1
}
```

### Что показать

| Поле | Описание |
|---|---|
| `message` | Строка в чат Minecraft. Цвета через `&` (приложение А), плейсхолдеры (раздел 16) |
| `title`, `subtitle` | Большой текст по центру экрана и подпись под ним. Время показа — `titleTicks` в общих настройках (60 тиков = 3 с) |
| `actionbar` | Текст над хотбаром |
| `toast`, `toastText` | Всплывающее уведомление в правом верхнем углу (как достижение): заголовок и строка под ним. Висит 6 секунд |
| `sound`, `volume`, `pitch` | Звук, слышный **только тебе** (не записывается с игрового звука отдельно — его слышит захват игры). Id из игры, `minecraft:` можно не писать. Громкость 0–2, высота 0.5–2. Неизвестный звук один раз помечается в логе |

### Что сделать

| Поле | Описание |
|---|---|
| `commands` | Список команд Minecraft. Выполняются от твоего имени с правами оператора на встроенном сервере (читы включать не нужно; вывод скрыт, если не включён `showCommandOutput`). Начальный `/` не нужен. Специальная команда **`delay N`** — пауза N тиков (20 = 1 с) перед следующей |
| `randomOne` | `true` — выполнить **одну случайную** команду из списка вместо всех по порядку (рулетка «Сюрприз») |
| `repeat` | Сколько раз повторить **список команд**: число (`"3"`) или плейсхолдер (`"{amount}"`). Пусто = 1 |
| `repeatPer` | Делитель: `"repeat": "{amount}", "repeatPer": 100` → один повтор на каждые 100 битс (37 битс → 1 раз, 250 → 2 раза) |
| `maxRepeat` | Потолок повторов (защита: 10 000 битс при `repeatPer: 100` дадут не 100 криперов, а `maxRepeat`) |
| `repeatDelay` | Пауза между повторами, тиков. В командах доступны `{i}` (номер повтора, с 1) и `{repeat}` (всего) |
| `reply` | Ответ от твоего имени в чат платформы события: Twitch (`chatReplies`), VK (`vk.replies` + `chatReplies`), YouTube (`youtube.replies`); для игры — в выбранные чаты (`gameEventsSettings`) |

Эффекты (`message`, `title`, `toast`, звук) показываются **один раз**, повторяются только команды.

### Условия

| Поле | Описание |
|---|---|
| `chance` | Шанс срабатывания, 0–100 %. При неудаче показывается `failMessage`, кулдаун всё равно ставится, баллы за награду не возвращаются |
| `failMessage` | Сообщение в чат игры при неудаче |
| `cooldown` | Общий кулдаун действия, секунд. Пока идёт — событие не выполняется: зрителю уходит `cooldownReply`, за награду возвращаются баллы, в истории — `кулдаун N с` |
| `userCooldown` | Кулдаун на одного зрителя, секунд (по логину). Работает одновременно с общим |
| `permission` | Только чат-команды: `everyone`, `subscriber`, `vip`, `moderator`, `broadcaster` (каждый уровень включает предыдущие: модератор может всё, что VIP) |
| `aliases` | Только чат-команды: другие имена (`["зомби", "z"]`), регистр не важен, префикс писать не нужно |
| `enabled` | `false` — действие временно выключено, но не удалено. У наград: активация придёт, но ничего не сделает (и баллы не вернутся — отключи награду и на Twitch) |

### Для наград за баллы (используются `/twitch rewards sync`)

| Поле | Описание |
|---|---|
| `cost` | Стоимость в баллах при создании (0 → `rewardsSettings.defaultCost`, по умолчанию 500) |
| `prompt` | Описание награды, которое видят зрители |
| `input` | `true` — зритель обязан ввести текст; он попадёт в `{message}` |
| `color` | Цвет плашки `#RRGGBB` |
| `cooldown` | При создании передаётся Twitch (и VK как `repair_timeout`, если ≥ 10 с) как глобальный кулдаун награды (плюс проверяется самим модом) |
| `pool` | `bad` / `good` / `any` — **случайное событие из ценника донатов**: мод равновероятно выбирает включённую запись `donationTiers` с нужным знаком (☠ / ★ / любую) и после собственного действия награды выполняет её команды, звук, заголовок и тост. Текст записи (её `message`, `reply`) не показывается — его заменяет сообщение награды с `{picked}` / `{picked_text}` / `{picked_full}`. Пусто — обычная награда. Если у награды есть своя таблица `loot`, она имеет приоритет |

### Таблица лута

| Поле | Описание |
|---|---|
| `loot` | Список записей `{ "name", "weight", …любые поля действия… }` — см. раздел 15 |
| `name`, `weight` | Только у записей лута: название (подставляется в `{loot}`) и вес |

## 15. Таблицы лута

Таблица лута — это «случайный подарок»: при срабатывании действия из списка `loot` выпадает **ровно одна** запись.
Шанс записи = её `weight` / сумма весов всех включённых записей.

```json
"follow": {
  "message": "&d{user} &7теперь следит за каналом! Подарок: &6{loot}",
  "toast": "&dНовый фолловер", "toastText": "{user} — {loot}",
  "commands": ["particle minecraft:heart ~ ~2 ~ 1 1 1 0 20"],
  "loot": [
    { "name": "3 печенья",          "weight": 40, "commands": ["give @s minecraft:cookie 3"] },
    { "name": "золотое яблоко",     "weight": 20, "commands": ["give @s minecraft:golden_apple 1"] },
    { "name": "алмаз",              "weight": 8,  "commands": ["give @s minecraft:diamond 1"] },
    { "name": "ЗАЧАРОВАННОЕ яблоко","weight": 2,  "commands": ["give @s minecraft:enchanted_golden_apple 1"],
      "title": "&6ДЖЕКПОТ!", "sound": "minecraft:ui.toast.challenge_complete" }
  ]
}
```

Как это работает:

- Запись выбирается **до** показа основного действия, поэтому `{loot}` можно писать уже в `message`, `title`, `toast` основного действия.
- Сначала выполняется основное действие (эффекты + команды с повторами), затем — эффекты и команды выпавшей записи.
  У записи могут быть любые поля действия: свой заголовок, звук, ответ в чат, даже свои повторы.
- Запись с `enabled: false` или `weight: 0` не выпадает. Если таблица пуста — `{loot}` пустой.
- Таблицу можно добавить **любому** действию: награде, чат-команде, порогу битсов, цели, донату.
- Повторы (`repeat`) основного действия не влияют на лут: подарок выпадает один раз.
- В экране настроек: редактор действия → **Таблица лута (N)** → список записей, у каждой — редактор, вес и **Тест**.

По умолчанию таблицы лута есть у фоллова, подписки и рейда (см. приложение Г).

## 16. Плейсхолдеры

Подставляются в любое текстовое поле действия и в команды.

| Плейсхолдер | Значение |
|---|---|
| `{user}` | отображаемое имя зрителя (для рейда — имя рейдера-стримера; для цели — кто внёс последний вклад) |
| `{user_login}` | логин зрителя (латиницей, строчными) |
| `{amount}` | число события: битсы / месяцы / подарки / зрители / стоимость награды / сумма доната / порог цели |
| `{message}` | текст зрителя: к битсам, к ресабу, ввод к награде, аргументы чат-команды, сообщение донатера |
| `{reward}` | название награды за баллы |
| `{tier}` | уровень подписки: `1`, `2`, `3`, `Prime` |
| `{command}` | имя чат-команды (без префикса) |
| `{player}` | твой ник в Minecraft |
| `{i}`, `{repeat}` | номер текущего повтора (с 1) и общее число повторов |
| `{loot}` | название выпавшей записи таблицы лута (пусто, если таблицы нет); для наград с `pool` — то же, что `{picked}` |
| `{picked}` `{picked_text}` `{picked_full}` | награды с `pool` (по умолчанию «Пакость» и «Подарок»): название выпавшей записи ценника без значка (`Тыква`), её описание без «задонатил(а)» (`тыква на голову!`), название со значком (`☠ Тыква`). В обычных событиях пусто |
| `{platform}` | `Twitch`, `VK Video Live`, `YouTube Live` или `Minecraft` для события игры |
| `{goal}`, `{target}`, `{times}` | в действии цели или сбора: название, порог (цель сбора), сколько раз достигнута/закрыт |
| `{sum}` | донаты и закрытие сбора: сумма с символом валюты (`500 ₽`); для остальных событий = `{amount}` |
| `{currency}` | донаты и сбор: код валюты (`RUB`) |
| `{fund}` `{fund_name}` `{fund_current}` `{fund_target}` `{fund_left}` `{fund_percent}` `{fund_currency}` `{fund_donors}` | **в любом действии**: главный сбор средств (первый видимый) — заголовок без цветов, имя, собрано, цель, осталось, процент, символ валюты, число вкладов. Удобно для чат-команды `!сбор` |
| `{source}` | донаты: `DonationAlerts` / `DonatePay` |
| `{seconds}` | только в `cooldownReply`: сколько секунд ждать |
| `{permission}` | только в `noPermissionReply`: нужный уровень прав словами |
| `{session_follows}` `{session_subs}` `{session_gifts}` `{session_bits}` `{session_raids}` `{session_rewards}` `{session_commands}` `{session_donations}` `{session_donation_sum}` `{session_events}` `{session_minutes}` | статистика текущей сессии **с учётом текущего события** (удобно для `reply` в `!stats`) |
| `{donation_prices_bad}` `{donation_prices_good}` `{donation_prices}` `{donation_currency}` | **в любом действии**: ценник донатов одной строкой из общей таблицы `donationTiers` — только ☠ («30 Тыква · 50 Голод · …»), только ★, всё вместе (с префиксами); символ основной валюты. Отключённые записи пропускаются. Для `!плохое` / `!хорошее` |
| `{deaths}` `{deaths_total}` `{advancements}` `{advancements_total}` `{bosses}` `{bosses_total}` `{last_death}` `{session_time}` | **в любом действии**: счётчики событий игры за сеанс и за всё время (файл `twitchcraft-stats.json`), текст последней смерти, время с запуска игры («1 ч 05 мин»). Для `!смерти` / `!время` |
| `{stream_time}` `{viewers}` `{live}` `{stream_title}` `{stream_game}` | **в любом действии**: стрим Twitch — «1 ч 20 мин» / «не в эфире» / «неизвестно», зрителей, `да`/`нет`, название, категория. Обновляется раз в минуту (`GET /streams`) |
| `{youtube_viewers}` `{youtube_live_time}` `{youtube_title}` `{youtube_channel}` `{youtube_broadcast_url}` `{youtube_id}` | **в любом действии**: YouTube Live — зрителей эфира, сколько идёт эфир («1 ч 20 мин»), заголовок трансляции, название канала, ссылку `https://youtu.be/<id>` и id эфира. Пока эфир не найден или `youtube.trackViewers: false` — пусто; зрители и время обновляются раз в `youtube.viewersIntervalSeconds` (раздел 22б) |
| `{youtube_quota}` `{youtube_quota_left}` | **в любом действии**: сколько единиц дневной квоты YouTube Data API уже израсходовано и сколько осталось до порога `youtube.quotaBudget`. Строка «≈1 234 / 9 000 ед., сброс в 10:00 (через 3 ч 05 мин)» показывается в `/twitch youtube` и `/twitch youtube info` |
| `{cause}` | событие «смерть»: причина как в игре («Dед утонул», «Dед was slain by Zombie») |
| `{advancement}` `{advancement_text}` `{advancement_kind}` | события достижений: название, описание, вид (`достижение` / `цель` / `испытание`) |
| `{boss}` `{killer}` | событие «босс повержен»: кто повержен, кем (пусто, если тобой) |
| `{dimension}` `{dimension_id}` | событие «смена измерения»: «Нижний мир» / «Край» / «Верхний мир» (для модовых — имя из id), `minecraft:the_nether` |
| `{clip_url}` `{why}` | текст сообщения о клипе (`clips.clipChatText`): ссылка и повод («смерть», «донат 100 ₽ от Вася», «босс: Иссушитель», «вручную») |
| переменные аддонов | аддон может добавить своё: хук `registerVariable` (раздел 22г). Пример аддона «Артефакты»: `{artifact_count}`, `{artifact_total}`, `{artifact_destroyed}`, `{artifact_last}`, `{artifact_limit}` и боссовые — `{boss_name}`, `{boss_alive}` (`да`/`нет`), `{boss_next}`, `{boss_defeats}`, `{boss_spawned}`. Занятые имена мода (`{user}`, `{amount}` и т.п.) аддон переопределить не может |

Безопасность подстановки: тексты зрителей очищаются от кавычек, переводов строк, управляющих символов и `§`-кодов, а
плейсхолдеры подставляются **за один проход** — зритель не может написать `{player}` в сообщении и получить подстановку,
и не может «сломать» команду кавычкой. Неизвестные плейсхолдеры остаются как есть.

## 17. Награды за баллы канала

### Две случайные награды по умолчанию

С версии 1.6 в конфиге по умолчанию **две** награды по **250 баллов** (вместо дюжины примеров):

| Награда | `pool` | Что происходит |
|---|---|---|
| **Пакость** | `bad` | случайное ☠ событие из ценника донатов — одно из 25 (тыква на голову, голод, зомби-волна, молния, наковальня, крипер, … вплоть до Иссушителя) |
| **Подарок** | `good` | случайное ★ событие — одно из 25 (перекус, опыт, салют, алмазы, тотемы, незерит, … вплоть до «Легенды») |

Выбор **равновероятный** среди включённых записей ценника с нужным знаком; цена записи роли не играет — за 250 баллов может выпасть
и «Тыква», и «Иссушитель». В чат пишется `☠ Вася активировал(а) «Пакость» — выпало: Ночь ужасов! наступает ночь ужасов!`, зрителю уходит ответ
`Вася, выпало: ☠ Ночь ужасов!`, затем выполняются команды выпавшей записи (её звук, заголовок и тост тоже). Записи ценника с `enabled: false`
в розыгрыше не участвуют; если подходящих записей нет совсем — награда выполнит только своё действие и один раз предупредит в чате
(вернуть ценник: `/twitch donations preset`). Список возможных событий зрители могут спросить командами `!плохое` и `!хорошее`.

Хочешь третью награду «Рулетка» с любым исходом — добавь действие с `"pool": "any"`. Хочешь награды с фиксированным эффектом — добавь их
без `pool` (см. [раздел 6](#6-первая-своя-награда-за-баллы)). При обновлении со старых версий: нетронутые награды-примеры заменяются этими
двумя, а твои собственные остаются и к ним лишь добавляются недостающие «Пакость»/«Подарок».

### Сопоставление

Ключ в `rewards` сравнивается с **названием** награды на Twitch или VK Video Live без учёта регистра и пробелов по краям. Если точного
совпадения нет — используется запись `"*"` (если она есть). По умолчанию `"*"` просто пишет в чат «активировал награду …».
Одна и та же запись обслуживает обе платформы: кулдауны и цели у неё общие.

### Два способа завести награды

1. **Автоматически** — `/twitch rewards sync` или кнопка **Создать награды на Twitch**. Мод берёт все ключи из `rewards`
   (кроме `*`), сравнивает с наградами, уже существующими на канале, и создаёт недостающие: цена `cost`
   (или `defaultCost`), описание `prompt`, требование ввода `input`, цвет `color`, кулдаун `cooldown`. Существующие награды
   не меняются. Итог в чате: `создано N, уже было M, ошибок K`.
2. **Вручную** в панели Twitch (*Монетизация → Баллы канала → Управление наградами*) с теми же названиями.

На VK Video Live то же самое делает `/twitch vk rewards sync` (кнопка **Создать награды на VK**): цена `cost`, описание `prompt`,
обязательность текста `input`, кулдаун `cooldown` (≥ 10 с). Награды VK, созданные вручную в студии, тоже работают — лишь бы совпадало название.

### Подтверждение и возврат баллов

Twitch разрешает менять статус активации **только наградам, созданным этим же приложением** (то есть через `rewards sync`).
Для них при включённом модуле `rewardManagement`:

- `autoFulfill: true` — после успешного выполнения активация помечается «выполнено» (исчезает из очереди запросов на Twitch);
  лотерея с неудачей тоже считается выполненной.
- `autoRefund: true` — баллы возвращаются зрителю, если событие **не выполнилось**: награда на кулдауне, очередь переполнена
  или очищена, ты не в мире при выключенной очереди (в истории такие события видны как `пропущено: …`).

Награды, созданные вручную или другими программами, мод выполняет, но вернуть/подтвердить не может (Twitch отвечает 403) —
об этом один раз пишется в лог, дальше такие награды просто пропускаются при подтверждении.

На VK Video Live ограничения «только свои награды» нет: при `vk.manageDemands: true` мод **подтверждает** выполненные запросы и
**отклоняет** невыполненные (баллы возвращаются зрителю) для любой награды канала — нужно право `channel:points:rewards:demands`
(выдаётся при входе). Запросы, которые VK подтвердил сам (награда с автоподтверждением), мод не трогает.

### Настройки

```jsonc
"rewardsSettings": { "autoFulfill": true, "autoRefund": true, "defaultCost": 500 }
```

`/twitch rewards` — список настроенных наград с числом команд; клик по названию — тест.

## 18. Чат Twitch в игре

Модуль `twitchChat` показывает сообщения чата Twitch в чате Minecraft:

```
[T] ⚔★ Ник: текст сообщения
```

- `[T]` — префикс (`twitchChat.prefix`, по умолчанию `&5[T]&r `).
- Значки (`showBadges`): ♛ стример, ⚔ модератор, ◆ VIP, ★ подписчик/основатель.
- Ник — в цвете зрителя из Twitch (слишком тёмные цвета осветляются). Битсы в сообщении — `[N битс]`.
- Сообщения ботов из `ignoredUsers` не показываются. Ссылки в тексте не кликабельны (безопасность).
- `hideCommands: true` — сообщения-команды (`!zombie`) не показываются, а только выполняются.
- Быстро включить/выключить: `/twitch chat on|off` (это переключение модуля).

**Общий чат (Shared Chat).** Когда ты стримишь в общем чате с другим каналом, в твою подписку приходят и сообщения,
написанные в чате партнёра. Они показываются с серой пометкой `[логин_канала]` (`showSharedChat`, по умолчанию `true`),
но **не запускают твои чат-команды** (`sharedChatCommands`, по умолчанию `false`) — зрители чужого канала не могут спавнить
тебе мобов. Оба переключателя — в *Общие настройки → Чат Twitch*. Если выключить оба — сообщения общего чата игнорируются полностью.

Сообщения можно показывать ещё и табличками, которые висят в воздухе перед игроком, — см. [раздел 18а](#18а-таблички-чата-в-воздухе).

Если у тебя стоит другой мод, показывающий чат Twitch (например, Take Your Stream Chat), выключи здесь `twitchChat`, чтобы не дублировать. YouTube чат использует отдельные `youtube.showChat` и `youtube.chatPrefix`; настройки описаны в §22б.

## 18а. Таблички чата в воздухе

Сообщения чата Twitch, VK и YouTube можно показывать **табличками, которые висят в воздухе перед игроком**: над центром
экрана, на расстоянии нескольких блоков. Табличка остаётся на месте в мире, когда ты поворачиваешься, и плавно гаснет.
Включено по умолчанию; строка в окне чата тоже остаётся (можно выключить). Таблички появляются только тогда, когда включён чат
своей платформы (модуль `twitchChat`, `vk.showChat` или `youtube.showChat`): выключил чат — пропали и таблички.

Табличка состоит из шапки и текста: в шапке метка платформы из префикса (`[T]`, `[VK]`, `[YT]`), значки, ник в цвете зрителя
и битсы (для Shared Chat — `[канал]`); ниже — текст сообщения, перенесённый по словам. Длинный текст обрезается после трёх
строк и заканчивается на «…».

Как ведут себя таблички:

- Появляются за четверть секунды, в последнюю секунду жизни гаснут. Новые встают у базы, старые — над ними (стопкой).
- Если между тобой и табличкой стоит блок (стена, потолок), табличка не рисуется. Если блок ближе расстояния `distance`,
  табличка встаёт перед ним.
- Не показываются, когда открыт любой экран (инвентарь, чат, настройки, пауза), при скрытом интерфейсе (F1) и на экране F3.
- При смене мира или измерения убираются.
- Сообщения из `ignoredUsers` и (при `hideCommands`) команды-сообщения табличками не становятся — их правила те же, что и у строки в чате.

**Разбить табличку рукой.** Наведи прицел на табличку и один раз нажми ЛКМ: она разлетится на осколки, со звуком и взмахом
руки. Разбить можно табличку в досягаемости руки — примерно в 6 блоков или ближе (дистанция по умолчанию как раз 6). Дальше
рамка не подсвечивается и клик проходит мимо. Рамка таблички становится золотистой, когда по ней можно кликнуть. Клик
достаётся табличке, только если она ближе блока или моба за ней; иначе удар идёт миру как обычно. Ограничение: если держать
ЛКМ, пока прицел на табличке, блок за ней в досягаемости может продолжать ломаться, поэтому кликай, а не держи.

Настройки — экран **Общие настройки → Таблички в воздухе** или раздел `chatSigns` в `twitchcraft.json`:

| Поле | По умолчанию | Значение |
|---|---|---|
| `enabled` | `true` | показывать табличками |
| `keepInChat` | `true` | дублировать строкой в окне чата; `false` — только таблички |
| `seconds` | `10` | сколько секунд табличка висит в воздухе (1–120) |
| `maxVisible` | `5` | сколько табличек одновременно (1–12); лишние самые старые гаснут за 0,3 с |
| `distance` | `6` | расстояние до табличек, блоки (2–30); на нём размер «100 %». Ближе — крупнее (до 160 %), дальше — мельче (до 50 %) |
| `scale` | `100` | размер табличек, проценты (25–300) |

```json
"chatSigns": { "enabled": true, "keepInChat": false, "seconds": 8, "maxVisible": 4, "distance": 6, "scale": 120 }
```

Чтобы сообщения показывались только табличками, выключи `keepInChat` — строк в окне чата не будет. Чтобы убрать таблички совсем,
поставь `enabled: false` — строки в чате останутся как раньше. Таблички рисуются поверх мира как интерфейс: проверка «за стеной» делается лучом раз в 0,15 с, поэтому при
выходе из-за угла табличка может появиться с небольшой задержкой.

## 19. Чат-команды зрителей

Модуль `chatCommands` обрабатывает команды Twitch и VK. Зритель пишет в чат `!имя аргументы`; для YouTube тот же список команд отдельно разрешается флагом `youtube.chatCommands` (см. §22б), без зависимости от модуля Twitch `chatCommands`.

### Распознавание

1. Сообщение начинается с префикса `chatCommandPrefix` (по умолчанию `!`).
2. Первое слово после префикса (без учёта регистра) ищется среди ключей `chatCommands` и их `aliases`.
   Ключи и алиасы можно писать с префиксом или без — `"zombie"` и `"!zombie"` равнозначны.
3. Остальной текст попадает в `{message}` (например, `!say привет всем` → `{message}` = `привет всем`).
4. Сообщения от `ignoredUsers` игнорируются. Собственные ответы мода (`reply`), вернувшиеся через чат, командами не считаются.
5. Сообщения из общего чата (Shared Chat) — только если `sharedChatCommands: true`.

### Права

Уровень зрителя определяется по значкам в твоём канале: `broadcaster` > `moderator` > `vip` > `subscriber` (и основатель) > `everyone`.
Команда с `"permission": "vip"` доступна VIP, модераторам и стримеру. Если прав нет — зрителю уходит `noPermissionReply`.

### Кулдауны

`cooldown` — для всех, `userCooldown` — для конкретного зрителя. На кулдауне зрителю уходит `cooldownReply` с `{seconds}`.
Кулдауны считаются отдельно для каждой команды, награды и порога.

### Пример команды только с ответом (без эффектов)

```json
"stats": { "reply": "За стрим: фолловов {session_follows}, сабов {session_subs}, битсов {session_bits}", "cooldown": 30 }
```

Команды по умолчанию: `!zombie` (`!зомби`), `!heal` (`!хил`, только подписчики), `!stats`, `!fund` (`!сбор`), `!ценник`, `!плохое`, `!хорошее` — см. приложение Г.

## 20. Ответы в чат Twitch

Модуль `chatReplies` (право Twitch `user:write:chat`) управляет ответами Twitch и VK. Мод пишет **от твоего имени**:

- `reply` любого действия (после выполнения);
- автоответы: `chatReplies.cooldownReply` (`@{user}, подожди ещё {seconds} с`) и `chatReplies.noPermissionReply`
  (`@{user}, эта команда только для {permission}`). Пустая строка — не отвечать;
- `/twitch say <текст>` — написать в Twitch.

Для VK дополнительно нужны `vk.replies` и VK scope `chat:message:send`. Для YouTube действует независимый `youtube.replies`, scope
`youtube.force-ssl` и активная трансляция; ответы и `/twitch youtube say <текст>` идут в YouTube live chat. У каждой площадки собственная очередь
и пауза отправки. Общие объявления игры, таймеров и клипов идут по отдельным флагам маршрутизации (§22б–22в), а не зависят от `chatReplies`.

Лимит Twitch — 20 сообщений за 30 секунд; мод держит очередь (до 20 сообщений) и сам выдерживает паузы, лишнее отбрасывает
с пометкой в логе. Если соответствующий модуль/платформенный флаг выключен или права нет — ответы молча пропускаются (остальное работает).

## 21. Цели

Цель — счётчик «каждые N … → награда». Модуль `goals`.

```json
{ "name": "Фолловеры", "type": "follows", "target": 10, "repeat": true, "enabled": true,
  "action": { "message": "&6ЦЕЛЬ! Ещё {target} фолловеров (уже {times}-й раз)!", "title": "&6+{target} ФОЛЛОВЕРОВ!",
              "sound": "minecraft:ui.toast.challenge_complete", "commands": ["give @s minecraft:diamond 3"] } }
```

| Поле | Значение |
|---|---|
| `name` | уникальное название (показывается в оверлее, используется в командах) |
| `type` | что считаем — таблица ниже |
| `target` | сколько набрать (≥ 1) |
| `repeat` | `true` — после достижения счётчик уменьшается на `target` и цель идёт дальше («каждые N»); `false` — один раз (потом показывается ✔) |
| `enabled` | выключенная цель не считает и не показывается |
| `action` | обычное действие; плейсхолдеры `{goal}`, `{target}`, `{times}`, `{user}` (последний вклад) |

| `type` | Что прибавляется |
|---|---|
| `follows` | 1 за фоллов |
| `subs` | 1 за подписку и ресаб, N за N подарков |
| `gifts` | N за N подарочных подписок |
| `bits` | количество битсов |
| `raids` | 1 за рейд |
| `raidViewers` | зрителей в рейде |
| `rewards` | 1 за активацию награды |
| `points` | стоимость активированной награды в баллах |
| `donations` | 1 за донат |
| `donationSum` | сумма доната в основной валюте |
| `events` | 1 за любое событие (кроме чата, чат-команд и самих целей) |

Правила:

- **Тестовые события и повторы (F9) в цели не засчитываются.** Подвинуть счётчик руками: `/twitch goals add <цель> <n>`
  (n может быть отрицательным). Проверить награду цели: `/twitch test goal <цель>` или кнопка **Тест**.
- Одно событие двигает цель **не больше чем на 5 срабатываний** подряд (рейд на 1000 зрителей при цели «каждые 10» не устроит
  100 наград за тик). Остаток остаётся в прогрессе и «догоняется» следующими событиями.
- Прогресс хранится в `config/twitchcraft-goals.json` и переживает перезапуск. Если мод не запускался дольше
  `goalsSettings.resetAfterHours` (12 ч; 0 — никогда), счётчики обнуляются — новый стрим начинается с нуля.
- `goalsSettings.announceProgress: true` — после каждого вклада в чат игры пишется `Цель «Фолловеры»: 7/10`
  (только если включён `showEventsInChat`).
- Прогресс виден в оверлее (`◎ Фолловеры: 7/10 ×2` — ×2 = уже достигнута дважды) и по `/twitch goals`
  (клик по цели = тест, при наведении — кто внёс последний вклад).
- `/twitch goals reset` — сбросить все, `/twitch goals reset <цель>` — одну.

Цели по умолчанию: Фолловеры (каждые 10), Подписки (каждые 5), Битсы (каждые 1000), Донаты (каждые 1000 ₽), Рейдеры (каждые 100 зрителей).

## 21а. Сборы средств — полоса-боссбар

Сбор средств — это «копилка с целью», которая рисуется **вверху экрана как полоса здоровья босса**: те же спрайты, та же
ширина (182 px), тот же отступ (12 px) и тот же шаг, что и у настоящих боссов. Над полосой — текст
`Сбор на стрим: 3 500 / 10 000 ₽ (35%)`, справа 8 секунд после вклада — `+500 ₽ · Ник`. Модуль `fundraisers`.

Отличие от цели типа `donationSum`: цель — счётчик «каждые N» для наград, а сбор — одна конкретная сумма, которую видно
постоянно, которая **не сбрасывается сама** (ни после стрима, ни через 12 часов) и которую можно пополнять вручную.

```json
{ "enabled": true, "visible": true, "name": "Сбор", "title": "&6Сбор на стрим", "target": 5000,
  "color": "pink", "style": "notched_10", "format": "{title}: {current} / {target} {currency} ({percent}%)",
  "countDonations": true, "bitsRate": 0, "subValue": 0, "pointsRate": 0, "hideWhenCompleteSeconds": 0,
  "action": { "message": "&6СБОР ЗАКРЫТ! &7Собрано &6{sum}&7 — спасибо всем!", "sound": "minecraft:ui.toast.challenge_complete" } }
```

| Поле | Значение |
|---|---|
| `name` | уникальное имя — для команд (`/twitch fund add <имя> …`) и файла прогресса; без кавычек |
| `title` | заголовок над полосой; пусто — показывается `name`; можно `&`-цвета |
| `target` | цель, целое число ≥ 1 **в основной валюте** (`donations.currency`, по умолчанию RUB) |
| `color` | `pink` `blue` `red` `green` `yellow` `purple` `white` — цвета ванильных боссбаров |
| `style` | `progress` (сплошная), `notched_6`, `notched_10`, `notched_12`, `notched_20` (с делениями) |
| `format` | текст над полосой; плейсхолдеры `{title} {current} {target} {left} {percent} {currency} {last} {last_amount} {donors}` |
| `countDonations` | донаты DonationAlerts / DonatePay идут в сбор (сумма в основной валюте, как у порогов) |
| `bitsRate` | сколько единиц валюты даёт **1 битс** (0 — не считать; `0.7` → 100 битс = 70 ₽) |
| `subValue` | сколько даёт **одна подписка** (новая, ресаб; подарок × количество) |
| `pointsRate` | сколько даёт **1 балл канала** при активации награды (`0.1` → награда за 500 баллов = 50 ₽) |
| `hideWhenCompleteSeconds` | через сколько секунд после закрытия спрятать полосу; 0 — оставить заполненной |
| `visible` | `false` — полоса не рисуется, но вклады считаются (можно включить в нужный момент) |
| `enabled` | `false` — сбор полностью выключен |
| `action` | что сделать, когда сумма достигла цели; плейсхолдеры `{goal}` (имя), `{target}`, `{sum}` (цель с валютой), `{currency}`, `{times}` (какой раз закрыт), `{user}` (чей вклад закрыл) |

Общие настройки `fundraiserSettings`: `y` — отступ полосы сверху (12; если на экране есть настоящий босс — поставь 31 и больше,
иначе полосы наложатся), `lastContributionSeconds` — сколько показывать «+500 ₽ · Ник» (8; 0 — не показывать), `animate` — плавное заполнение.

Правила:

- **Тестовые события и повторы (F9) в сборы не засчитываются.** Проверить эффект закрытия: `/twitch test fund <имя>` или кнопка **Тест**.
- Ручные вклады: `/twitch fund add <имя> <сумма> [от кого]` — наличные, перевод на карту, донат мимо сервисов. Может закрыть
  сбор (эффект сработает). Отрицательная сумма уменьшает прогресс и, если он упал ниже цели, снова «открывает» сбор.
- `/twitch fund set <имя> <сумма>` — поставить сумму точно (эффект закрытия **не** срабатывает, только пересчитывается состояние).
- Сбор закрывается **один раз**: сумма сверх цели продолжает копиться (`120%`), но эффект не повторяется. Чтобы начать новый
  сбор — `/twitch fund reset <имя>` (обнулить) или `/twitch fund target <имя> <новая цель>` (поднять планку — сбор снова открыт).
- Полоса прячется вместе с интерфейсом (F1) и на экране F3. Больше трети экрана по высоте полосы не занимают (как у ванили).
- Прогресс (сумма, число вкладов, последний вклад, сколько раз закрыт) хранится в `config/twitchcraft-fundraisers.json`
  и переживает перезапуск. Переименование сбора на экране настроек переносит прогресс.
- Чат-команда по умолчанию `!fund` / `!сбор` отвечает в чат Twitch текущим состоянием (через `{fund_*}`, см. раздел 16).
- Полосу видишь только ты (и захват игры) — зрители на Twitch видят её через OBS как часть картинки.

Команды: `/twitch fund` (список с прогрессом), `create <имя> <цель> [заголовок]`, `remove`, `show`, `hide`, `add`, `set`,
`target`, `title`, `reset [имя]` — полный список в разделе 28. Экран: **Сборы средств (боссбар)** (раздел 27).

Сбор по умолчанию «Сбор» (цель 5 000 ₽, заголовок «Сбор на стрим») **виден сразу**. Не нужен — `/twitch fund hide Сбор`, или
сними галочку *Показывать* в редакторе, или удали его ✖, или выключи модуль `fundraisers`.

## 22. Донаты: DonationAlerts и DonatePay

Оба сервиса — отдельные модули (`donationAlerts`, `donatePay`), работают независимо от Twitch, подключаются автоматически
при входе в мир и видны в `/twitch status`, `/twitch donations`, оверлее (`DA●` / `DP●`) и на экране **Донаты**.

### Как донат превращается в эффект

1. Определяется сумма **в основной валюте** `donations.currency` (по умолчанию `RUB`), дробная часть отбрасывается.
   DonationAlerts сам пересчитывает чужие валюты в валюту твоего аккаунта (мод берёт поле `amount_in_user_currency`);
   DonatePay работает в рублях.
2. Сумма меньше `donations.minAmount` (по умолчанию 1) — донат показывается в логе и пропускается.
3. Таблица порогов: если для сервиса заполнена своя (`donationAlertsTiers` / `donatePayTiers`), используется **она целиком**;
   иначе общая `donationTiers`. Выбирается самый большой порог ≤ суммы.
4. Выполняется действие. Плейсхолдеры: `{user}`, `{sum}` (`500 ₽`), `{amount}`, `{currency}`, `{message}`, `{source}`.
   `donations.showMessage: false` — текст донатера не показывать в чате игры.
5. Донат засчитывается в цели `donations` / `donationSum` и в статистику.

### Ценник по умолчанию: 25 пакостей ☠ и 25 подарков ★

С версии 1.5.0 общая таблица `donationTiers` — это готовый **ценник из 51 события**: «Спасибо» за любую мелочь (от 1 ₽),
25 негативных и 25 позитивных событий на суммы от 30 до 5 000 ₽. Плохое и хорошее **чередуется** через ступень
(30 ☠ Тыква, 40 ★ Перекус, 50 ☠ Голод, 60 ★ Исцеление …), поэтому зритель сам решает, помочь или навредить, — просто суммой.
Полная таблица — в `README.md` (раздел 5в) и в `release/ЦЕННИК.md` (готовый текст для панели под стримом).

Правила, которые стоит объяснить зрителям:

- Срабатывает **самый большой порог ≤ суммы**: 45 ₽ → «40 ★ Перекус», 250 ₽ → «250 ☠ Молния», 999 ₽ → «950 ☠ Иссушение».
  Хочешь конкретное событие — донать **ровно его цену** (или чуть больше, но меньше следующей ступени).
- Ступени плотные (шаг 10–20 ₽ внизу), так что «округлить» донат вверх почти всегда означает попасть на соседнее событие
  противоположного знака. Это сделано специально — ценник надо показывать.
- Ценник — «полный хаос»: заряженный крипер (320), наковальня (280), Хранитель (2 500) и Иссушитель (4 000) **могут сломать
  постройки и убить персонажа**. Не хочешь такого — выключи тумблером или замени (экран **Донаты → Общие эффекты**).

Как мод отличает плохое от хорошего: по префиксу в поле `name` — `☠ ` (плохое) или `★ ` (хорошее). Добавишь свою запись с таким
префиксом — она попадёт в нужный список автоматически; без префикса — в «прочие».

Инструменты:

| Что | Где |
|---|---|
| Посмотреть ценник в игре | `/twitch donations prices` или кнопка **Показать ценник в чате** на экране **Донаты** |
| Зрителю спросить в чате Twitch | `!ценник` (`!prices`, `!донат`, `!цены`) — как это работает; `!плохое` (`!bad`, `!пакости`); `!хорошее` (`!good`, `!подарки`). Ответы строятся из текущей таблицы через плейсхолдеры `{donation_prices_bad}`, `{donation_prices_good}`, `{donation_prices}`, `{donation_currency}` (нужен scope `user:write:chat`, см. раздел 20) |
| Вернуть ценник по умолчанию после своих правок | `/twitch donations preset` → `/twitch donations preset confirm` или кнопка **Ценник по умолчанию (51)**; старый конфиг сохраняется в копии `twitchcraft.json.bak-<дата>` |
| Обновление с 1.4.0 | если старую таблицу из 10 записей ты не менял — она заменится новым ценником автоматически (копия файла — `twitchcraft.json.bak-v5`); изменённую таблицу мод не трогает |

Отключённые записи (тумблер «Включено» = выкл) из ответов `!плохое` / `!хорошее` пропадают, а в `/twitch donations prices`
помечаются «(выкл)». Ответ в чат Twitch не длиннее 500 символов — поэтому плохое и хорошее идут двумя разными командами.

Проверка без денег: `/twitch test donation [сумма] [сообщение]` или кнопка **Тест доната** — тестовые донаты не попадают в цели и статистику.

### DonationAlerts

- Вход: OAuth в браузере (implicit flow) с правами `oauth-user-show` (кто ты), `oauth-donation-subscribe` (получать донаты),
  `oauth-donation-index` (прочитать список донатов — только чтобы **догнать** пропущенное за время обрыва связи).
  Токен хранится в `config/twitchcraft-donations.json`, живёт долго; если его отзовут — мод напишет «токен недействителен — войди заново».
- Для приёма токена мод на время входа (до 10 минут) открывает порт `donations.callbackPort` (8631) **только на localhost**.
  Redirect URI приложения должен быть `http://localhost:<порт>/da`. Ссылка входа содержит одноразовый `state`, приёмник отвергает
  запросы с чужих сайтов и принимает токен один раз. Если DonationAlerts вернёт OAuth-ошибку на callback, подсказка появится и в браузере, и в игровом чате.
- Получение донатов — WebSocket Centrifugo (`centrifugo.donationalerts.com`), мгновенно. Короткоживущие токены соединения мод
  продлевает сам; при обрыве переподключается (2, 4, 8… до 60 с) **тихо** — в чат пишет только если перерыв дольше минуты;
  после переподключения проверяет через API, не пришло ли что-то, пока сокет был мёртв; повторы одного доната отбрасываются.
- Команды: `/twitch donations da client <id>`, `da login`, `da cancel`, `da logout`, `da connect`, `da disconnect`.

### DonatePay

- Нужен **API-ключ** из кабинета (*Настройки → API*). Это секрет: храни как пароль. Передаётся: `/twitch donations dp key <ключ>`
  (ключ — одно слово без пробелов) или поле на экране **Донаты** → **Применить ключ**. Мод проверяет ключ запросом профиля.
- Реального времени у DonatePay нет — мод **опрашивает** API раз в `donations.donatePayPollSeconds` (минимум и по умолчанию 20 с —
  ограничение самого DonatePay: не чаще раза в 20 с на ключ). Задержка эффекта — до 20 с.
- При первом подключении запоминается последний существующий донат (старые не проигрываются). Платёж в статусе `wait`
  (зритель ещё платит) мод дожидается и выполняет, когда он станет `success` (до часа); `cancel` пропускает;
  **тестовые оповещения из кабинета** (статус `user`) выполняет как тест.
- Если ключ отклонён — модуль останавливается до нового ключа. «Слишком частые запросы» — другая программа использует тот же ключ.
- Команды: `/twitch donations dp key <ключ>`, `dp logout`, `dp connect`, `dp disconnect`.

### Общие команды и настройки

`/twitch donations` — статус и подсказки; `/twitch donations connect` / `disconnect` — оба сервиса сразу.

```jsonc
"donations": {
  "currency": "RUB",             // основная валюта: пороги и цели donationSum считаются в ней
  "minAmount": 1,                // донаты меньше — игнорируются (0 — не игнорировать)
  "donationAlertsClientId": "",  // Client ID приложения DonationAlerts
  "donatePayPollSeconds": 20,    // период опроса DonatePay (не меньше 20)
  "callbackPort": 8631,          // порт для входа в DonationAlerts (1024–65535)
  "showMessage": true            // показывать текст донатера в чате Minecraft
},
"donationTiers":       { "1": {…}, "30": {…}, "40": {…}, … },   // общие эффекты по сумме (ценник 51 запись)
"donationAlertsTiers": {},   // свои эффекты только для DonationAlerts (пусто = общие)
"donatePayTiers":      {}    // свои эффекты только для DonatePay (пусто = общие)
```

Экран **Донаты**: Client ID, кнопки *Открыть страницу приложений* / *Скопировать Redirect URI* / *Войти в DonationAlerts*,
поле API-ключа DonatePay (*Где взять ключ*, *Применить ключ*, *Удалить ключ*), валюта, минимум, период опроса, порт,
кнопки **Общие эффекты (N)**, **Только DonationAlerts (N)**, **Только DonatePay (N)** и **Тест доната**. Настройки применяются
кнопкой **Сохранить**.

## 22а. VK Video Live

Интеграция с **live.vkvideo.ru** через официальный DevAPI (`apidev.live.vkvideo.ru`) и WebSocket. Работает параллельно с Twitch:
события VK помечены платформой (`{platform}` = `VK Video Live`, в истории и журнале — `VK`), но проходят через те же действия,
очередь, кулдауны, цели и сборы. Пошаговая настройка — [раздел 8а](#8а-подключаем-vk-video-live).

### Что приходит с VK и куда попадает

| Событие VK | Что делает мод | Условие |
|---|---|---|
| Сообщение в чате | показывает в чате игры с префиксом `vk.chatPrefix` (`&9[VK]&r `); упоминания → `@ник`, смайлы → `:имя:`, ссылки — текстом | модуль `vkVideoLive` + `vk.showChat` |
| `!команда` в чате | та же таблица `chatCommands`, те же права (владелец канала = стример, модератор = модератор, остальные = зрители) и кулдауны | + `vk.chatCommands` и модуль `chatCommands` |
| Запрос награды за баллы | действие из `rewards` по названию; `{amount}` = цена, `{message}` = текст зрителя; статус запроса — см. ниже | + `vk.rewards` (модуль `channelPoints` не требуется) |
| Новый подписчик канала (фоллов) | действие `follow`, цели и сборы по фолловам | + `vk.follows` |
| Платная подписка (если VK пришлёт её в журнал) | действие `subscribe` / `resub` как Tier 1 | + `vk.follows` |
| Начало/конец эфира | запоминает id эфира (нужен для отправки в чат) и статус «эфир / нет эфира» в `/twitch vk` | — |

Повторы отбрасываются: один и тот же запрос награды может прийти по двум каналам WebSocket — выполнится один раз; повторный фоллов того же
человека за сессию игнорируется. Незнакомые типы событий пишутся в лог (первые три раза каждого типа), а при `vk.debugEvents: true` —
все события целиком: типы событий WebSocket VK официально не задокументированы, так что если что-то не срабатывает — включи и пришли лог.

### Статус запросов наград

При `vk.manageDemands: true` (по умолчанию) после выполнения действия запрос **подтверждается**, а если событие не выполнилось
(кулдаун, очередь переполнена/очищена, ты не в мире при выключенной очереди) — **отклоняется с возвратом баллов**. Запросы с автоподтверждением
VK (статус `approved` уже при получении) не трогаются. Выключи флаг, если хочешь разбирать запросы вручную в студии VK.

После каждого (пере)подключения мод забирает через API **необработанные запросы за последние 10 минут** — если игра была закрыта или связь рвалась,
зрители не останутся без эффекта (и без баллов).

### Ответы в чат VK

`reply`, `cooldownReply`, `noPermissionReply` и `/twitch vk say` уходят в чат VK при `vk.replies: true` и включённом модуле `chatReplies`.
Между сообщениями пауза 1,5 с; при ответе VK «слишком часто» мод повторяет через 3 с; одинаковые сообщения подряд VK может отклонить
(`same_message`) — это нормально. Для отправки нужен **идущий эфир** (VK требует id трансляции) — вне эфира мод один раз предупредит.
Свои сообщения мод помнит и не выполняет их как команды.

### Раздел `vk` конфига

```jsonc
"vk": {
  "clientId": "",                                  // ID приложения с dev.live.vkvideo.ru/apps (секрет — в twitchcraft-vk.json)
  "callbackPort": 8638,                            // порт для входа: Redirect URI приложения = http://localhost:<порт>/vk
  "channelUrl": "https://live.vkvideo.ru/dedworkshop", // канал (ссылка или имя); пусто — свой канал вошедшего аккаунта
  "showChat": true,                                // чат VK в игре
  "chatPrefix": "&9[VK]&r ",
  "chatCommands": true,                            // !команды зрителей VK
  "rewards": true,                                 // запросы наград → действия rewards
  "follows": true,                                 // фолловы → действие follow
  "replies": true,                                 // ответы в чат VK
  "manageDemands": true,                           // подтверждать/отклонять запросы наград
  "debugEvents": false                             // все события WebSocket в лог
}
```

Экран **VK Video Live** в настройках повторяет эти поля плюс кнопки *Открыть страницу приложений*, *Скопировать Redirect URI*, *Войти/Выйти*,
*Подключить/Отключить*, *Создать награды на VK*, *Тест награды «Пакость»*.

### Команды

| Команда | Описание |
|---|---|
| `/twitch vk` | статус: приложение, вход, канал, подписки WebSocket (чат / награды / журнал), эфир, число событий |
| `/twitch vk app <id> <секрет>` | сохранить приложение (секрет — в `config/twitchcraft-vk.json`) |
| `/twitch vk channel <ссылка или имя>` | какой канал слушать (переподключится, если был подключён) |
| `/twitch vk login` / `cancel` / `code <код>` | начать вход через браузер / отменить / завершить вручную кодом из адресной строки |
| `/twitch vk logout` | отозвать токен, удалить его (секрет приложения остаётся) |
| `/twitch vk connect` / `disconnect` | подключиться / отключиться (после `disconnect` автоподключение выключено до `connect`) |
| `/twitch vk say <текст>` | написать в чат VK |
| `/twitch vk rewards sync` | создать на VK недостающие награды из конфига |
| `/twitch vk debug on\|off` | писать все события WebSocket VK в лог |
| `/twitch vk test chat <текст>` / `follow` / `reward <название>` | тестовые события «как будто с VK» (локально, без API) |

### Как это устроено

- **Вход**: OAuth 2.0 Authorization Code — ссылка на `auth.live.vkvideo.ru`, код возвращается на `http://localhost:8638/vk`
  (приёмник проверяет одноразовый `state`, работает ≤ 10 минут), обменивается на токены по `client_id:secret`. Запрашиваемые права:
  `chat:message:send, channel:points, channel:points:rewards, channel:points:rewards:demands`. Токен продлевается сам (по сроку и при 401);
  если продлить не удалось — `/twitch vk login` заново.
- **События**: WebSocket Centrifugo (`pubsub-dev.live.vkvideo.ru`); подписки на каналы `chat`, `info`, `channel_points` и приватные
  `private_info`, `private_channel_points` (для них берутся токены подписки — они доступны только владельцу канала). Соединение переподключается
  с нарастающей паузой (2…60 с), сторож — 2 минуты тишины, токен сокета обновляется по требованию сервера.
- **Чужой канал**: слушать можно и чужой канал (чат, публичные запросы наград), но подтверждение запросов, журнал и отправка в чат могут быть
  недоступны — об этом будет запись в логе.

## 22б. YouTube Live

YouTube подключён как отдельная платформа (`TwitchEvent.platform = YOUTUBE`) через **YouTube Data API v3**. Читаются только события,
для которых есть сопоставимая модель в TwitchCraft; Twitch-фолловы, рейды, битсы и Channel Points не выдумываются.
Быстрая установка — [раздел 8б](#8б-подключаем-youtube-live).

### OAuth Desktop + PKCE

Создай в Google Cloud Console проект, включи YouTube Data API v3, настрой экран согласия OAuth и добавь OAuth Client ID типа **Desktop app**.
Client Secret мод не принимает и не хранит. OAuth запрашивает только `youtube.readonly` и `youtube.force-ssl` (чтение и отправка live chat).
Авторизация — Authorization Code + PKCE S256, с одноразовым `state`, loopback callback и таймаутом входа. По умолчанию URI —
`http://localhost:8640`; Desktop OAuth использует localhost loopback и порт, указанный в настройках. На экране YouTube можно скопировать URI.
Если браузер открыл redirect, но локальный callback недоступен, вставь полный URL в `/twitch youtube code <URL>`.

- Client ID хранится в `youtube.clientId` основного `config/twitchcraft.json`.
- Access token, refresh token, scopes и профиль канала находятся отдельно в `config/twitchcraft-youtube.json` (секретный файл).
- Access token обновляется по сроку через refresh token. `/twitch youtube logout` пытается отозвать токен Google, затем удаляет локальные токены.
- `/twitch youtube login` открывает новый сеанс; `/twitch youtube cancel` отменяет ожидание callback.

### Настройки и флаги

```jsonc
"youtube": {
  "clientId": "",               // OAuth Client ID типа Desktop app (не Client Secret)
  "callbackPort": 8640,          // loopback URI http://localhost:<порт>
  "showChat": true,              // показывать обычный чат в Minecraft
  "chatPrefix": "&c[YT]&r ",     // префикс в чате Minecraft
  "chatCommands": true,           // разрешать общие chatCommands только на YouTube
  "paidMessages": true,           // Super Chat, Super Sticker и Fan Funding
  "memberships": true,            // новые/продлеваемые членства и групповые подарки
  "replies": true,                // автоответы и /twitch youtube say
  "debugEvents": false,           // расширенная диагностика polling и незнакомых событий
  "pollMaxResults": 2000,         // сообщений за один запрос live chat (200…2000): больше — реже запросы
  "trackViewers": true,           // зрители и время эфира через videos.list ({youtube_viewers})
  "viewersIntervalSeconds": 60,   // как часто обновлять данные эфира (15…3600 с; 1 запрос = 1 единица квоты)
  "quotaBudget": 9000,            // дневной порог квоты Data API в единицах (0 — только лимит Google 10 000)
  "quotaGuard": true,             // остановить опрос, когда порог исчерпан; возобновится после сброса Google
  "control": true,                // управление эфиром и модерация: go / title / ban / unban / delete
  "showModeration": false,        // писать в чат игры действия модераторов YouTube (баны, удаления, спам)
  "defaultTimeoutSeconds": 300    // тайм-аут по умолчанию для /twitch youtube ban <ник> (0 — постоянный бан)
}
```

Включи модуль `/twitch module youtubeLive on`. Он управляет всей интеграцией; внутри него YouTube-флаги независимы от Twitch `twitchChat`,
`chatCommands`, `chatReplies` и VK-флагов. `showChat` и `chatCommands` можно выключить по отдельности. `replies` отвечает только за исходящие
сообщения в YouTube; отправка также требует авторизации с `youtube.force-ssl`, активного эфира и разрешения YouTube API.
`control` разрешает команды управления эфиром и модерации (`go`, `title`, `ban`, `unban`, `delete`) — они используют тот же scope
`youtube.force-ssl`, повторно входить в Google не нужно. `showModeration` показывает в чате игры, кого забанили или чьё сообщение удалили;
в конвейер событий такие сообщения не попадают и наград не выдают. `trackViewers` и `viewersIntervalSeconds` отвечают за `{youtube_viewers}`,
`quotaBudget` и `quotaGuard` — за дневной расход квоты (см. «Polling, квота и статус эфира» ниже).

### События YouTube и общие действия

| `liveChatMessages.list` type | Событие TwitchCraft | Данные |
|---|---|---|
| `textMessageEvent` | `CHAT` (из `!имя` получается общее `CHAT_COMMAND`) | текст, имя и channel ID автора; Moderator/Owner/Sponsor используются как роли |
| `newSponsorEvent` | `SUBSCRIBE` | новое платное членство, уровень YouTube попадает в `{tier}` |
| `memberMilestoneChatEvent` | `RESUB` | `{amount}` = номер месяца членства; комментарий — `{message}` |
| `membershipGiftingEvent` | `GIFT_SUB` | `{amount}` = число подаренных членств; анонимный даритель — «Аноним» |
| `superChatEvent`, `superStickerEvent`, `fanFundingEvent` | `DONATION` | сумма из `amountMicros` округляется вниз до целого; валюта YouTube — `{currency}`, исходная площадка — `{source}` |

Все сопоставленные события помечены платформой YouTube, попадают в общий `EventProcessor`, журнал, статистику, цели и действия. Поэтому
общие действия `subscribe`, `resub`, `giftSub`, `donationTiers` и `chatCommands` можно использовать повторно. Порог доната сравнивает
целую сумму в валюте, которую передал YouTube; конвертации в `donations.currency` нет. Для членств YouTube уровня `{tier}` — текстовое имя
уровня, а не Twitch-код `1`/`2`/`3`/`prime`; таблицы `subscribeByTier` и `resubByTier`, если ключ не совпадает, переходят к общему действию.

`giftMembershipReceivedEvent` (уведомление получателя группового подарка) и служебные типы игнорируются: групповой подарок учитывается один раз
по `membershipGiftingEvent`. Super Chat / Sticker обрабатываются только при `paidMessages: true`; членства — при `memberships: true`.

Служебные типы (`placeholderMessageEvent`, `viewerEngagementMessageEvent`, `pollEvent`, `giftMembershipReceivedEvent`) мод пропускает молча и не
пишет их в лог как «неизвестные». Отдельно читаются сообщения модерации — они не становятся событиями, но при `showModeration: true` видны в чате игры:

| type | Что показывает мод |
|---|---|
| `userBannedEvent` | «⚠ Ник получил тайм-аут 5 мин» (`banType: temporary`) или «⚠ Ник заблокирован в чате» (`permanent`) |
| `markChatItemAsSpamEvent` | «⚠ Сообщение Ник помечено как спам» |
| `markChatItemsAsDeletedEvent` | «⚠ Сообщения удалены модератором» |

Проверить разбор таких сообщений без эфира: `/twitch youtube test ban`.
YouTube не предоставляет Twitch-фолловы, рейды, Cheers/битсы или активации Channel Points — действий и подписок для них нет.

### Polling, квота и статус эфира

`YoutubeLive` ищет канал OAuth-аккаунта через `channels.list`, затем активную трансляцию через `liveBroadcasts.list(broadcastStatus=active)`.
Профиль канала кэшируется на 30 минут — `channels.list` не вызывается на каждом круге поиска. Пока эфира нет, поиск повторяется с нарастающим
интервалом: 30 с → 1 мин → … → 5 мин (верхняя граница), поэтому простой канал тратит единицы квоты, а не тысячи. Как только эфир найден,
интервал поиска сбрасывается.

После обнаружения `liveChatId` читает `liveChatMessages.list` (стоимость — 5 единиц за запрос). Первый успешный ответ используется только для
получения `nextPageToken` и `pollingIntervalMillis`: его сообщения намеренно пропускаются, чтобы не исполнять старые команды. Дальше каждый запрос
продолжает с предыдущим `nextPageToken`; следующий запрос планируется не раньше `pollingIntervalMillis` (с нижней защитной границей 1 с). Ошибка
истёкшего page token возвращает polling к новой точке отсчёта, не проигрывая накопленную историю. За один запрос мод берёт `youtube.pollMaxResults`
сообщений (по умолчанию 2000 — максимум API): при плотном чате это в разы меньше запросов и расхода квоты, чем 200.

Ошибки и сбои сети не приводят к долбёжке API: после каждой неудачи пауза удваивается — 2 с → 4 с → 8 с → … → 60 с (верхняя граница), а после успешного
запроса возвращается к обычному интервалу. На `429` и `503` мод уважает заголовок `Retry-After` от Google. Ответ `quotaExceeded` (403) и
исчерпание порога `youtube.quotaBudget` останавливают опрос: мод один раз пишет в чат игры, сколько единиц израсходовано и когда квота сбросится,
и ждёт — не дольше 30 минут за подход и до сброса Google (полночь по тихоокеанскому времени США). Если порог увеличил или снял, опрос возобновится
сразу после сохранения настроек (`/twitch reload`) или `/twitch youtube connect`.

Расход квоты мод считает сам (Google не возвращает его в ответах) по опубликованным ценам: `liveChatMessages.list` — 5, `channels.list`,
`liveBroadcasts.list`, `videos.list` — 1, записывающие операции (`liveChatMessages.insert/delete`, `liveChatBans.insert/delete`,
`liveBroadcasts.update/transition`) — 50. Цена `liveBroadcasts.transition` Google не опубликована — мод считает её с запасом как обычную запись.
Счётчик привязан к Client ID (квота считается на проект Google Cloud, а не на аккаунт), сохраняется в `config/twitchcraft-youtube.json`,
переживает перезапуск игры и обнуляется на новые квотные сутки. Смотреть: `/twitch youtube` или `/twitch youtube info`.

Данные эфира (зрители, время начала, заголовок) приходят из `videos.list?part=snippet,liveStreamingDetails` — 1 единица квоты раз в
`youtube.viewersIntervalSeconds` (по умолчанию 60 с, минимум 15 с) и только пока эфир активен. Отсюда берутся `{youtube_viewers}`,
`{youtube_live_time}`, `{youtube_title}` и `{youtube_broadcast_url}`. Если `trackViewers: false`, запрос не делается вовсе.
Когда чат завершился (`offlineAt`, `liveChatEnded`) или эфир пропал, мод возвращается к поиску трансляции, а счётчики эфира обнуляются.

Статус: `/twitch youtube` показывает вход, модуль, канал, активный `liveChatId`, флаги, расход квоты и зрителей; `/twitch youtube info` —
то же плюс id и ссылку эфира, время начала, сколько эфир идёт, участников чата, следующую попытку опроса и последнюю ошибку. Команды:

| Команда | Назначение |
|---|---|
| `/twitch youtube` | статус и настройки |
| `/twitch youtube client <Client ID>` | сохранить публичный OAuth Client ID в основном конфиге |
| `/twitch youtube login` / `cancel` / `code <полный URL>` | начать вход / отменить / обработать URL callback вручную |
| `/twitch youtube connect` / `disconnect` | подключить / отключить; после ручного отключения переподключение — через `connect` |
| `/twitch youtube say <текст>` | тестово отправить сообщение в активный чат |
| `/twitch youtube info` | подробный статус: эфир, зрители, время, квота, участники, следующая попытка, ошибки |
| `/twitch youtube go live\|testing\|complete` | начать эфир / перейти в режим теста / завершить трансляцию (`liveBroadcasts.transition`) |
| `/twitch youtube title <текст>` | поменять заголовок трансляции (`liveBroadcasts.update`) |
| `/twitch youtube ban <ник\|channelId> [секунды]` | тайм-аут зрителя; без секунд — `youtube.defaultTimeoutSeconds`, `0` — постоянный бан |
| `/twitch youtube unban <ник\|id бана>` | снять бан/тайм-аут (`liveChatBans.delete`) |
| `/twitch youtube delete <ник\|id сообщения>` | удалить последнее сообщение зрителя (`liveChatMessages.delete`) |
| `/twitch youtube logout` | отозвать токен и удалить локальные credentials (счётчик квоты сохраняется) |
| `/twitch youtube debug on\|off` | сохранять подробности API/polling в лог |
| `/twitch youtube test chat <текст>` / `member` / `milestone` / `gift` / `superchat` / `sticker` / `funding` / `ban` | синтетические события; реальные API-запросы не выполняются |

### Управление эфиром и модерация чата

Всё это работает через публичный YouTube Data API v3 и уже выданный при входе scope `youtube.force-ssl` — повторный вход в Google не нужен.
Нужны включённый модуль `youtubeLive`, вход под аккаунтом владельца канала (или модератора чата) и флаг `youtube.control`.

| Действие | Метод API | Цена, единиц |
|---|---|---|
| `go testing` / `go live` / `go complete` | `liveBroadcasts.transition` | 50 (оценка: Google цену не публикует) |
| `title <текст>` | `liveBroadcasts.list` + `liveBroadcasts.update` | 1 + 50 |
| `ban <ник> [сек]` | `liveChatBans.insert` (`temporary` / `permanent`) | 50 |
| `unban <ник\|id>` | `liveChatBans.delete` | 50 |
| `delete <ник\|id>` | `liveChatMessages.delete` | 50 |

Какая трансляция управляется: сначала активная (`broadcastStatus=active`), а если активной нет — ближайшая запланированная
(`broadcastStatus=upcoming`, самая ранняя `scheduledStartTime`). `go testing` доступен только если у трансляции включён мониторинг потока
(`contentDetails.monitorStream.enableMonitorStream`), `go live` — если видеопоток уже идёт в Studio/OBS; иначе Google отвечает ошибкой,
которую мод переводит в понятный текст («поток не активен», «трансляция уже в этом состоянии», «нет прав на трансляции»,
«нельзя забанить владельца или модератора»).

Кого банить/удалять: ник берётся из реестра участников чата, который мод ведёт во время опроса (300 последних зрителей, запись живёт 6 часов),
поэтому команды работают и без id. Можно передать и точный `channelId` (начинается с `UC`), id сообщения или id бана. Если нику соответствует
несколько зрителей, мод ничего не делает и перечисляет варианты — лучше передать `channelId`. Свои баны мод запоминает, поэтому
`unban <ник>` снимает именно тот тайм-аут, который был выдан из игры.

Чего публичный API **не позволяет** (это только YouTube Studio / Live Control Room): медленный режим чата, режим «только участники/подписчики»,
полное отключение чата, метки и главы трансляции, а также запуск и остановка самого видеопотока (энкодера). Мод не имитирует эти функции:
`go live` переводит трансляцию в статус live на стороне YouTube, но поток всё равно нужно запустить в OBS/Studio.

На экране **YouTube Live** те же действия продублированы кнопками: «В эфир», «Тест», «Завершить», «Сменить заголовок» (поле заголовка рядом),
«Обновить данные» (зрители и квота немедленно) и ссылка «Квоты Google Cloud» на консоль проекта.

Исходящие сообщения игры (события игры, таймеры, ссылки Twitch-клипов) могут быть направлены в YouTube отдельными флагами
`gameEventsSettings.toYoutube`, `timers[].youtube`, `clips.postClipToYoutube`; это не включает YouTube-чат обратно в игру.

## 22в. События игры → чат, клипы и метки, таймеры чата

Три функции 1.7.0, которые работают «в обратную сторону»: не зрители влияют на игру, а игра рассказывает зрителям, что случилось.

### События игры → чат (модуль `gameEvents`)

| Ключ в `gameEvents` | Когда | Как мод это замечает | По умолчанию в чат |
|---|---|---|---|
| `death` | ты умер | здоровье игрока ≤ 0 / экран смерти; причина — из сообщения о смерти (`death.*`), запасной вариант — из встроенного сервера | `💀 {cause} — смерть №{deaths} за стрим (всего {deaths_total}). F в чат!` |
| `advancement` | получено достижение | объявление `chat.type.advancement.task` — ловятся **все** достижения, включая модовые и из датапаков | `🏆 {player} получил достижение «{advancement}»: {advancement_text}` |
| `advancementGoal` | выполнена цель | `chat.type.advancement.goal`; если действие пустое — используется `advancement` | `🎯 {player} выполнил цель «{advancement}»: {advancement_text}` |
| `advancementChallenge` | пройдено испытание | `chat.type.advancement.challenge`; если пустое — `advancement` | `🔥 {player} прошёл испытание «{advancement}»: {advancement_text}! Это серьёзно` |
| `boss` | повержен дракон Края, иссушитель, варден или древний страж | событие смерти сущности на встроенном сервере (в одиночной игре) | `⚔ {player} победил босса: {boss}! Боссов за стрим: {bosses}` + заголовок «БОСС ПОВЕРЖЕН» и звук |
| `dimension` | перешёл в другое измерение | смена `level.dimension()` между тиками | `🌀 {player} отправился в {dimension}` |

Каждое событие — обычное **действие** (раздел 14): поле `reply` здесь публикует объявление в выбранные чаты по отдельности
(флаги `gameEventsSettings.toTwitch` / `toVk` / `toYoutube`; для YouTube нужен активный live chat и `youtube.force-ssl`). Это объявление
не зависит от автоответов модуля `chatReplies`; Twitch и VK требуют право отправки в чат у соответствующего аккаунта.
Остальные поля (заголовок, звук, команды) работают как обычно — например, можно повесить на смерть `playsound` или на босса фейерверк.

Особенности:
- События игры **не встают в очередь**, не считают паузу (F8) и лимит в минуту — объявление смерти через полчаса никому не нужно.
  Если ты в меню (не в мире) — событие отбрасывается. В цели и сборы они не попадают.
- Достижения объявляются только если в мире включено правило `announceAdvancements` (по умолчанию `true`; проверь, если играешь с датапаками,
  которые его выключают: `/gamerule announceAdvancements`). На сервере чужие достижения объявляются при `otherPlayers: true` (по умолчанию нет);
  смерти считаются только свои. Гибель питомцев с именем не считается смертью.
- `quietSecondsAfterJoin` (5 с) — тишина после входа в мир: если зашёл уже мёртвым или мир начинается с телепорта, ложного объявления не будет.
- Счётчики: за сеанс (`{deaths}`, `{advancements}`, `{bosses}`) и за всё время (`{deaths_total}` …) в `config/twitchcraft-stats.json`
  (`persistStats: false` — не хранить). `{session_time}` — время с запуска игры. Обнулить: `/twitch game reset [all]` или кнопка на экране.
- Готовые чат-команды зрителей (раздел `chatCommands`): `!смерти` (`!deaths`, `!смерть`, `!f`) → «💀 Смертей за стрим: {deaths}, за всё время: {deaths_total}»;
  `!время` (`!uptime`, `!time`, `!аптайм`) → «⏱ Стрим идёт {stream_time}; в игре — {session_time}, смертей {deaths}, достижений {advancements}». Обе с кулдауном 15 с.
- Проверка: `/twitch game test death` (и `advancement`, `goal`, `challenge`, `boss`, `dimension`) или кнопки *Тест* на экране — сообщение
  реально отправится в чаты, счётчики не изменятся. Состояние и счётчики — `/twitch game`.

### Клипы и метки стрима (модуль `clips`)

| Триггер | Настройки | Описание метки / повод клипа |
|---|---|---|
| смерть | `markerOnDeath`, `clipOnDeath` (оба включены) | «Смерть: {причина}» / «смерть» |
| донат | `donationFrom` (50 — в валюте `donations.currency`; 0 — выключить), `markerOnDonation`, `clipOnDonation` | «Донат 100 ₽ от Вася: текст» / «донат 100 ₽ от Вася». Тестовые донаты не считаются |
| босс | `markerOnBoss`, `clipOnBoss` | «Босс повержен: Иссушитель» / «босс: Иссушитель» |
| вручную | **F10**, `/twitch clip [повод]`, `/twitch marker [текст]`, кнопки на экране | что напишешь |

- **Метка** (`POST /streams/markers`) — точка на таймлайне записи стрима с описанием до 140 символов; видна в редакторе клипов/моментов Twitch
  (*Панель управления → Контент → Менеджер видео → Моменты*). Право `channel:manage:broadcast`. Кулдаун `markerCooldownSeconds` (10 с).
- **Клип** (`POST /clips`) — Twitch вырезает последние ~30 секунд эфира (без задержки записи — `has_delay=false`) и обрабатывает его ~15 секунд.
  Мод проверяет готовность через 15 с (потом ещё трижды по 10 с), затем пишет в чат игры «Клип готов: ссылка (обрезать)» и отправляет зрителям
  `clipChatText` (`🎬 Клип: {clip_url}`) в Twitch (`postClipToTwitch`), VK (`postClipToVk`) и YouTube (`postClipToYoutube`). Для YouTube нужен активный чат и `youtube.force-ssl`; право `clips:edit` относится только к созданию клипа на Twitch. Кулдаун `clipCooldownSeconds` (60 с) —
  при серии смертей клип будет один, метки — все.
- **Стрим не идёт** → Twitch отвечает 404. Автоматические триггеры молчат (раз в 5 минут — одна строка-напоминание в чат игры), ручные команды
  говорят прямо. Мод и сам знает, в эфире ли ты: раз в минуту спрашивает `GET /streams` (это же даёт `{stream_time}` и `{viewers}`).
- **Права после обновления**: токен, выданный до 1.7.0, не содержит `clips:edit` и `channel:manage:broadcast`. Сделай `/twitch logout`, затем
  `/twitch login` — экран *Клипы и метки* и `/twitch game` покажут «право есть». Статус запроса прав виден и в `/twitch status`.
- Клипы делаются от твоего имени (автор — твой канал), на Twitch они появляются в разделе *Клипы* как обычные.

### Таймеры чата (модуль `chatTimers`)

Таймер — сообщение бота раз в `intervalMinutes`, которое отправляется **только если с прошлого срабатывания зрители написали хотя бы
`minChatMessages` сообщений** (считаются события чата Twitch, VK и YouTube; `0` — писать всегда). Если чат тихий, таймер проверяет снова
через минуту и сработает, как только чат оживёт. Так бот не разговаривает сам с собой вне эфира и не раздражает тихий чат.

| Поле | Значение |
|---|---|
| `name` | имя (для команд `timers post|on|off`), уникально без учёта регистра |
| `enabled` | включён |
| `intervalMinutes` | интервал, 1–1440 |
| `minChatMessages` | минимум сообщений зрителей между срабатываниями, 0–1000 |
| `text` | текст; работают все общие плейсхолдеры: `{donation_prices_bad}`, `{donation_prices_good}`, `{donation_prices}`, `{donation_currency}`, `{deaths}`, `{deaths_total}`, `{session_time}`, `{stream_time}`, `{viewers}`, `{fund_*}`, `{session_*}`, `{player}`; `&`-цвета убираются |
| `twitch`, `vk`, `youtube` | куда писать на каждой платформе |

По умолчанию: **«ценник»** — каждые 15 минут при 3+ сообщениях: «Донат = событие в игре: ☠ пакости и ★ подарки — !ценник, !плохое, !хорошее.
Награды за баллы канала «Пакость» и «Подарок» (250) — случайное событие из ценника!»; **«соцсети»** — каждые 30 минут при 5+ сообщениях,
ссылки на twitch.tv/dedworkshop и live.vkvideo.ru/dedworkshop, **выключен** (включи, когда поправишь текст). Отсчёт первого срабатывания начинается с запуска игры (или с момента добавления таймера).
Команды: `/twitch timers` (список с «через N мин» / «ждёт живого чата»), `/twitch timers post <имя>` — отправить сейчас без условий,
`/twitch timers on|off <имя>`. На экране *Таймеры чата* — то же плюс *Предпросмотр* текста с подставленными значениями.

## 22г. Аддоны: «Артефакты» и API для своих аддонов

**Аддон** — это отдельный мод-файл (свой jar), который кладётся в `mods` рядом с TwitchCraft. Мод сам находит аддоны при
запуске, а аддон добавляет в TwitchCraft свои возможности. Аддон **необязателен**: без него мод работает как обычно,
а `/twitch addons` отвечает «аддоны не подключены». Ошибка аддона не роняет игру — мод пишет её в `logs/latest.log`
и продолжает работу.

### Аддон «Артефакты» (`artifact-addon-1.0.0.jar`)

Механики перенесены с серверного аддона CHRDK REBORN (VKChat Artifacts) — «идейно», под клиентскую сторону.

- **Как выбить артефакт**: битсы (1 за каждые 100), донаты (1 за каждые 100 ₽), подписки (1 за месяц), подаренные подписки
  (1 за каждые 5), рейды (1 за каждые 10 зрителей), награды за баллы канала (в названии есть «артефакт»/«artifact» — или
  награда, привязанная **по id**, см. ниже) и победы над боссами (50 %).
- **Редкости**: обычный 40 %, необычный 25 %, редкий 20 %, эпический 10 %, легендарный 4 %, мифический 0,1 %
  (мифический — без проклятия). Всего 56 баффов, 13 проклятий и 35 именных артефактов; часть мифических — особые:
  Перо Феникса, Сердце Дракона, Корона Бездны.
- **Проклятие**: пока артефакт лежит в инвентаре, оно растёт на **+1 % за 60 минут**. На 100 % артефакт рассыпается навсегда
  (предмет убирается командой; если прав на сервере нет — помечается «выгоревшим» и больше не действует).
- **Лимит**: не больше **5 артефактов** одновременно; шестой «ускользает» с сообщением. Записи «выгоревших»
  артефактов держат место в лимите, пока предмет лежит в инвентаре: выбросил (или мод убрал) — запись удаляется
  из `config/twitchcraft-artifacts-state.json`, а счётчики статистики остаются.
- **Баффы и проклятия** выдаются ванильными эффектами (`/effect give`); баффы без ванильного аналога пока только описаны
  в лоре предмета — им нужна серверная часть (см. `AUDIT.md`).
- **Команды активации**: `/artifact` (и `/артефакт`) — статус; `give [редкость] [ник]`, `held`, `list [редкость]`, `stats`,
  `curse <id> <процент>`, `break <id>`, `reload`.
- **Свои переменные для любых текстов мода**: `{artifact_count}`, `{artifact_total}`, `{artifact_destroyed}`, `{artifact_last}`,
  `{artifact_limit}` — работают в ответе в чате, чат-команде и таймере. Например, ответ чат-команды `!артефакты`:
  «в запасе {artifact_count} шт., всего выбито {artifact_total}…».

#### Боссы аддона (14 штук из серверного аддона)

Раз в **6 часов** (настраивается) в мире появляется один из 14 боссов — «Король Скелетов», «Кровавый Палач»,
«Королева Пауков», «Железный Титан», «Сумасшедший Житель», «Мутант-Иссушитель», «Ледяной Скиталец», «Огненный
Всполох», «Теневой Эндермен», «Король Слизней», «Ведьма Болот», «Пиглин-Воевода», «Утонувший Снайпер»,
«Фантомный Дракон» — со своими типом сущности, здоровьем (от 1024 до 6000), уроном, скоростью и набором навыков.

- **Расписание**: за **15 минут** до появления мод объявляет в чаты игры, Twitch и VK: кто идёт, координаты, сколько
  здоровья; при появлении — второй клич, полоса-боссбар и координаты. По умолчанию босс выходит в радиусе
  **5000 блоков** от игрока, координаты и время — в настройках аддона (`bosses`).
- **Навыки (11)**: `MINIONS` (три скелета), `LIGHTNING` (молния в игрока), `PULL` (рывок к боссу), `EARTHQUAKE`
  (левитация и мягкое падение), `POISON_CLOUD` (отравление в радиусе), `WEB_TRAP` (паутина под ногами), `TELEPORT`
  (босс прыгает на ±5 блоков), `BLINDNESS` (слепота), `WITHER_SKULL` (череп в игрока), `FREEZE` (сильное замедление),
  `FIRE_RING` (12 блоков огня вокруг босса). Навык срабатывает в **20 % случаев раз в 5 секунд**, если игрок ближе
  **24 блоков** к боссу — как в серверном аддоне.
- **Победа**: объявление в чаты («повержен, победитель — …»), +1 к счётчику побед и **50 %** на артефакт победителю.
- **Управление**: `/artifact boss` — кто сейчас в мире и когда следующий; `boss list` — все 14 с id и здоровьем;
  `boss now [id]` — вызвать немедленно; `boss stop` — убрать босса и полосу; `boss <id>` — вызвать конкретного.
- **Переменные для любых текстов**: `{boss_name}` (пусто, если босса нет), `{boss_alive}` (`да`/`нет`),
  `{boss_next}` («через 2 ч 15 мин» или «сейчас»), `{boss_defeats}`, `{boss_spawned}`.
- **Чат-команды**: `!босс` и `!боссы` — справка со статусом, счётчиками и временем следующего босса.
- **Кастомные триггеры аддона**: `v2` — «Босс появился», `v3` — «Босс повержен» (их можно перенастроить в своём
  аддоне или запустить вручную `/twitch addons fire v2`). К ним — и к любым другим слотам `v0…v3` — можно привязать
  свои действия из конфига: раздел `addonTriggers` в `config/twitchcraft.json` или экран `/twitch config`
  → *Триггеры аддонов* (например, фейерверк и сообщение в чат, когда босс вышел в мир).
- **События в моде**: появление и победа публикуются в общий конвейер как `bossSpawn` и `bossDefeat` — их видно в
  настройках «События игры → чат» (наравне с «Босс повержен» от ванильных боссов), и на них можно повесить свои
  действия в `config/twitchcraft.json`.

Боссы настраиваются в разделе `bosses` файла `config/twitchcraft-artifacts.json`:

```json
"bosses": {
  "enabled": true,
  "spawnIntervalSeconds": 21600,
  "announceBeforeSeconds": 900,
  "radius": 5000,
  "spawnNearPlayer": true,
  "distanceFromPlayer": 40,
  "skillChancePercent": 20,
  "skillCooldownSeconds": 5,
  "skillRange": 24,
  "bossBar": true,
  "artifactChancePercent": 50,
  "maxAliveSeconds": 1800,
  "disabled": [],
  "summonCommand": "summon {type} {x} {y} {z} {…}",
  "attributes": { "enabled": true, "maxHealth": "…:max_health", "attackDamage": "…:attack_damage", "movementSpeed": "…:movement_speed" },
  "texts": { "announce": "…", "spawn": "…", "defeat": "…", "noKiller": "…" }
}
```

Значения проверяются при загрузке: интервал — от 1 минуты до 24 часов, предупреждение — не больше интервала,
радиус случайной точки — 16…3 000 000 блоков, расстояние до игрока — 8…256, навыки — не чаще раза в 1…600 с
и не дальше 4…256 блоков, шансы — 0…100 %, `maxAliveSeconds` — 0…86 400. Пустые id в `disabled` убираются.
Ненужных боссов перечисли в `disabled` — они не будут выпадать в расписании; если выключены **все** боссы,
расписание просто откладывается на следующий интервал (мод не «долбит» каждую секунду). После правки —
`/artifact reload` (состояние и расписание сохранятся).

**`maxAliveSeconds` — страховка от «вечного» боя.** Победу аддон видит только во встроенном сервере одиночной игры
(событие смерти сущности); на чужом сервере смерть боса клиенту не видна, босс может despawn'нуться или быть убитым
чужой командой. Правило «один босс за раз» из-за этого навсегда занялось бы неотслеженным боссом, поэтому через
`maxAliveSeconds` (по умолчанию 30 минут) запись о боссе снимается, полоса убирается, а расписание продолжается;
самого босса в мире это не убивает — для этого остался `/artifact boss stop`. `0` — не снимать запись никогда.

**Награды по id (хук 3).** Чтобы привязать награду к аддону **по её id** (название стример может менять когда угодно),
впиши в `config/twitchcraft-artifacts.json`:

```json
"drops": { "rewardIds": { "f0a1b2c3-4567-89ab-cdef-0123456789ab": "Артефакт" } }
```

id награды виден в Twitch → *Управление наградами* → у награды → *Скопировать ID*. При активации такой награды аддон
выдаёт артефакт, а то, что зритель написал в поле награды, попадает отдельной строкой в чат игры и **аргументом** в обработчик.
Если награду переименуют, мод один раз предупредит в чате («привязан к награде «X», а сейчас активирована «Y»»), но привязка
по id продолжит работать. После правки файла — `/artifact reload`.

### Что аддон добавляет в мод: четыре хука API (версия 1)

Аддон описывает своё поведение **на Java** — интерфейсом `TwitchCraftAddon` и объектом `AddonContext`. Всё остальное делают
хуки; JSON-схема не нужна.

| Хук | Как выглядит у аддона | Что получается в моде |
|---|---|---|
| 1. Переменные | `context.registerVariable("boss_kills", e -> "7")` | плейсхолдер `{boss_kills}` в сообщениях, командах, HUD и оверлее |
| 2. Действия (флоу) | `context.registerAction(AddonAction.of("id", "Название", AddonTrigger.cheer(100)).elements(elements))` | мод сам следит за триггером и сам выполняет элементы: сообщение, титул, звук, команды, шанс, повторы |
| 3. Награды по id | `context.bindReward("f0a1-…", "Артефакт", (event, input) -> …)` | привязка к конкретной награде за баллы канала по **id**; ввод зрителя приходит аргументом |
| 4. Свои триггеры | `context.registerCustomTrigger(0, "Проверка", "вручную", trigger, actions)` | до **четырёх** кастомных триггеров `v0…v3` со своими условиями и действиями |

Готовые триггеры (`AddonTrigger`): `follow()`, `subscribe()`, `giftSub(5)`, `cheer(100)`, `raid(10)`, `donation(50)`,
`redemption(id)` — награда по id, `redemptionTitle("Артефакт")` — по названию, `chatCommand("артефакт", "artifacts")` —
чат-команда с синонимами (префикс берётся из настроек мода), `game(GAME_BOSS)` / `game(GAME_BOSS_SPAWN)` /
`game(GAME_BOSS_DEFEAT)` — события игры, `every()` и `custom(name, params, event -> …)` — своё условие.

Элементы (`AddonElements`) собираются по шагам: `message`, `title`, `actionbar`, `toast`, `sound`, `commands`, `randomOne`,
`chance`, `repeat` — как у действий из конфига, с плейсхолдерами и учётом `blockedCommands`.
Элементы действия четвёртого хука можно запустить **вручную без зрителей**: `/twitch addons fire v0` (это же делает аддон
«Артефакты» для проверки механики).

**Свои действия на триггеры аддона.** К кастомному триггеру привязывается обычное действие из конфига — раздел
`addonTriggers` в `config/twitchcraft.json` (ключ — слот: `"v0"`…`"v3"`, регистр не важен, годится и просто `"0"`…`"3"`)
или экран `/twitch config` → *Триггеры аддонов*. Когда условие триггера совпало с событием, мод выполняет привязанное
действие вместе с собственными действиями триггера — со всем, что умеют действия из конфига: шанс, кулдауны (ключ
`addonTrigger:v0`…), лут, повторы, ответ в чат. К плейсхолдерам события добавляются `{trigger}` (имя триггера)
и `{slot}` (например, `v2`). Ручной запуск `/twitch addons fire v0…v3` и кнопка «Тест» на экране тоже выполняют
привязанное действие (событие синтетическое — кулдауны не ставятся). Привязать действие можно заранее, до установки
аддона: оно заработает, как только слот будет зарегистрирован.

**Своё событие в мод: `publish`.** Если механика аддона — тоже игровое событие (босс вышел в мир, аирдроп приземлился),
аддон публикует его методом `context.publish(TwitchEvent.game(kind, …))` — событие проходит через общий конвейер:
действия из `config/twitchcraft.json`, хуки аддонов и журнал. Мод уже знает два таких вида: `bossSpawn` и `bossDefeat`
(боссы аддона «Артефакты») — они есть в настройках «События игры → чат», и их можно проверить командой
`/twitch game test bossSpawn`. Событие помечается синтетическим: без обращений к API площадок.

Что зарегистрировано — видно командами:

| Команда | Что показывает |
|---|---|
| `/twitch addons` | подключённые аддоны и счётчики: сколько переменных, действий, наград и триггеров |
| `/twitch addons actions` | действия аддонов и их триггеры |
| `/twitch addons rewards` | награды, привязанные к аддонам по id |
| `/twitch addons triggers` | кастомные триггеры `v0…v3` и привязанные к ним действия из конфига |
| `/twitch addons fire v0…v3` | ручной запуск кастомного триггера (тестовое событие, как `/twitch test …`); выполняет и привязанное действие из конфига |

Правила, чтобы аддоны не мешали друг другу: занятое имя переменной, id действия, награду или слот `v0…v3` чужой аддон
не перезапишет (будет предупреждение в логе), а свой аддон может обновить регистрацию — это нужно при перечитывании
настроек аддона. Ошибка аддона (упала переменная, условие или обработчик награды) гасится и пишется в лог;
остальные аддоны и мод продолжают работать.

**Своему аддону**: в `fabric.mod.json` объяви точку входа `twitchcraft-addon` и добавь TwitchCraft в `depends`:

```json
"entrypoints": { "twitchcraft-addon": [ "ru.example.MyAddon" ] }
```

Интерфейс — `dev.dedworkshop.twitchcraft.api.TwitchCraftAddon` (`id`, `title`, `version`, `onReady(AddonContext)`,
`onEvent(TwitchEvent)`, `onTick`, `onConfigChanged`, `onShutdown`), версия API — `TwitchCraftAddon.API_VERSION` (1).
`AddonContext` кроме хуков даёт папку `config/`, потоки мода (`scheduler()`, `worker()`), чат и объявления в чаты площадок,
`config()`, `placeholders()`, `runCommand(...)` (в одиночной игре — с правами оператора) и `publish(event)` —
событие аддона в конвейер мода.
Собрать аддон можно тем же `build.gradle`, что и мод (см. `README.md`, раздел 5е).

## 23. Очередь, пауза, лимиты

Все события проходят через одну очередь, которая обрабатывается **на игровом потоке** (эффекты и команды выполняются
безопасно, по одному событию за раз).

| Настройка | По умолчанию | Смысл |
|---|---|---|
| `queueWhenNotInWorld` | `true` | Событие пришло, пока ты в меню/на экране загрузки → ждёт в очереди до входа в мир. `false` — пропускается (за награду возвращаются баллы) |
| `maxQueuedEvents` | `20` | Длина очереди. Лишние события пропускаются с возвратом баллов и записью в историю (`очередь переполнена`) |
| `queueDelayTicks` | `20` | Минимальная пауза между событиями из очереди (20 тиков = 1 с), чтобы 10 наград не сработали одной кучей |
| `maxEventsPerMinute` | `30` | Больше событий за минуту — лишние ждут в очереди (не пропадают). 0 — без ограничения |

**Пауза** — `F8` или `/twitch pause` / `/twitch resume`. Во время паузы события только копятся. Оверлей показывает `‖ пауза`.
Пауза сбрасывается при перезапуске игры.

**Очередь** — `/twitch queue` показывает, что ждёт; `/twitch queue clear` очищает (баллы за награды возвращаются, события
попадают в историю со статусом `пропущено: очередь очищена`).

Кулдауны (общий и персональный) живут только в памяти и сбрасываются при перезапуске игры.

## 24. Оверлей

Модуль `overlay`. При запуске игры оверлей включён; `F7` или `/twitch overlay` скрывает/показывает его до перезапуска (при включении модуля `overlay` он тоже показывается заново).
Полоса сбора средств (раздел 21а) — отдельный элемент вверху экрана, F7 на неё не влияет.

```
Twitch ● онлайн   очередь: 2   DA●           ← строка состояния
❤ 12  ★ 3  ◆ 450  ⚡ 7   ₽1250                ← статистика сессии (showStats)
◎ Фолловеры: 7/10 ×1                          ← цели (showGoals)
◎ Донаты: 1250/1000 ✔
Zergik активировал «Крипер»                   ← последние события
Vasya зафолловил канал
```

- Состояние: `● онлайн` (зелёный), `○ оффлайн` (красный), `‖ пауза` (жёлтый); `очередь: N` — если очередь не пуста;
  `DA●` / `DP●` — подключённые сервисы донатов.
- Статистика: ❤ фолловы, ★ подписки (новые + ресабы + подарки), ◆ битсы, ⚡ награды, сумма донатов с символом валюты (если были).
- Цели: `◎ Название: прогресс/порог`, `×N` — сколько раз достигнута, ✔ — разовая цель выполнена.
- События: последние `maxEvents` (5) за `eventSeconds` (45 с), награды за баллы подсвечены фиолетовым.
- Оверлей скрывается вместе с интерфейсом (`F1`) и на экране отладки (`F3`).

```jsonc
"overlay": { "corner": "top-left", "maxEvents": 5, "eventSeconds": 45,
             "showStats": true, "showGoals": true, "margin": 4 }
```

`corner`: `top-left`, `top-right`, `bottom-left`, `bottom-right`. Всё это есть в *Общие настройки → Оверлей*.

## 26. Статистика, история, журнал

**Статистика сессии** (`/twitch stats`) — с момента запуска игры или последнего `/twitch stats reset`: минуты, событий, сообщений чата;
фолловы; сабы (+ресабов, подарено); битсы (сколько раз); рейды (зрителей); награды (баллов); чат-команды; целей достигнуто; донаты (сумма).
Те же числа доступны как `{session_*}` в текстах. Тесты и повторы в статистику не входят.

**История** (`/twitch history [n]`, по умолчанию 10, максимум 100) — последние события в памяти с временем и статусом:
`выполнено`, `кулдаун N с`, `нет действия`, `действие выключено`, `не повезло (шанс N%)`, `нет прав: нужно …`,
`пропущено: очередь переполнена`, `пропущено: очередь очищена`, `пропущено: игрок не в мире`. Тесты помечены `(тест)`.

**Журнал** (модуль `eventLog`) — файл `logs/twitchcraft-events.log` в папке игры, дописывается при каждом событии:

```
2026-10-05 20:14:02 | REWARD | Zergik (zergik) | amount=500 | reward=Крипер | выполнено | "бум"
2026-10-05 20:14:40 | FOLLOW | Vasya (vasya_tv) | amount=0 | выполнено
2026-10-05 20:15:03 | CHEER  | Аноним | amount=100 | кулдаун 12 с | test
```

Сообщения чата в журнал не пишутся. Когда файл превышает 5 МБ, он переименовывается в `twitchcraft-events.log.1`
(хранится одна предыдущая часть).

## 27. Экран настроек

Открывается из Mod Menu (*Моды → TwitchCraft → Настроить*) или командой `/twitch config` в мире. Игру экран не ставит на паузу —
можно настраивать прямо во время стрима. Кнопки с **Тест** работают только в мире.

| Экран | Что на нём |
|---|---|
| **Главный** | статус подключения, последнее сообщение мода, код входа (с кнопками *Открыть twitch.tv/activate* и *Скопировать код*), кнопки разделов, действия: *Войти в Twitch* / *Выйти из Twitch* (во время входа — *Отменить вход*), *Подключиться* / *Отключиться*, *Перечитать конфиг*, *Создать награды на Twitch* |
| **Модули** | 21 переключатель с подсказками; применяются сразу |
| **Общие настройки** | Client ID, автоподключение, события в чате, вывод команд, длительность заголовка; очередь (4 поля); чат Twitch (префикс, значки, скрывать команды, общий чат ×2); автоответы (2 текста); награды (автоподтверждение, автовозврат, цена по умолчанию); оверлей (угол, количество, секунды, статистика, цели, отступ); цели (сброс через N часов, объявлять прогресс); префикс чат-команд; чёрный список команд; игнорируемые логины. Поля помечают ошибки красным; применяются по **Сохранить** |
| **События Twitch** | фоллов, подписка, ресаб, подарки, рейд, битсы, донаты — кнопка **Изменить** (действие), **Пороги (N)** там, где есть пороги, и **Уровни (N)** у подписки/ресаба/подарков (действия по уровню 1/2/3/Prime); у каждого — **Тест** |
| **Награды за баллы** | список `rewards` с краткой сводкой по каждой (стоимость, команд, кулдаун, шанс); *+ Добавить*, у каждой строки — *Тест*, *Изменить*, ✖ (удалить с подтверждением). Название меняется в редакторе |
| **Чат-команды** | то же для `chatCommands` |
| **Пороги** | список порогов «от N» для выбранного события или донатов: *+ Добавить* (ключ — число), *Тест*, *Изменить*, ✖ |
| **Цели** | список целей с прогрессом: *+ Добавить*, *Сбросить прогресс*, у каждой — *Тест*, *Изменить*, ✖; редактор цели — имя, тип, порог, повторять, включена, действие |
| **Сборы средств (боссбар)** | список сборов с прогрессом (`Сбор · 3 500/10 000 ₽ · 35%`), *Изменить*, *Тест*, ✖; настройки полос (отступ сверху, секунды последнего вклада, анимация); *+ Добавить*, *Сбросить прогресс*. Редактор сбора — имя, заголовок, цель, **собрано** (правится руками), цвет, стиль, формат текста; что засчитывать (донаты, за 1 битс, за подписку, за 1 балл); показывать / включён / спрятать после закрытия; кнопка действия «когда сбор закрыт» |
| **Донаты** | DonationAlerts (Client ID, вход, статус), DonatePay (ключ, статус), общие настройки, три кнопки таблиц эффектов, *Тест доната* |
| **YouTube Live** | OAuth Client ID, loopback callback, отдельные флаги чата/команд/донатов/членств/ответов; вход/выход, подключение/отключение, debug и тесты; блок «Эфир» — зрители, время эфира, заголовок и ссылка, кнопки *В эфир* / *Тест* / *Завершить*, поле заголовка с *Сменить заголовок*, *Обновить данные*; блок «Опрос чата и квота» — `pollMaxResults`, `trackViewers`, `viewersIntervalSeconds`, `quotaBudget`, `quotaGuard`, строка расхода и ссылка *Квоты Google Cloud*; блок «Управление эфиром и модерация» — `control`, `showModeration`, `defaultTimeoutSeconds` |
| **События игры → чат** | шесть событий (смерть, достижение, цель, испытание, босс, измерение) — *Изменить* (редактор действия, поле «Объявление в чаты») и *Тест*; куда писать (Twitch / VK / YouTube), чужие достижения, тишина после входа, хранить счётчик; счётчики за сеанс и за всё время; *Обнулить счётчики сеанса* |
| **Клипы и метки** | состояние Twitch-стрима и прав, счётчики; *Сделать клип сейчас*, *Поставить метку*; когда срабатывать (смерть / донат от N / босс — метка и клип отдельно); ссылка в чаты Twitch / VK / YouTube, текст сообщения, кулдауны. Применяется при закрытии |
| **Таймеры чата** | список таймеров (`ценник · 15 мин · чат 3+ · Twitch+VK+YT · через 7 мин`), *Изменить*, *Сейчас* (написать в чат), ✖, *+ Добавить*; редактор — имя, включён, интервал, минимум сообщений, Twitch/VK/YouTube, текст, *Предпросмотр* (текст с подставленными значениями — только тебе) |
| **Редактор действия** | все поля из раздела 14 (набор полей зависит от типа: у наград есть стоимость/описание/ввод/цвет, у чат-команд — права/алиасы), многострочный список команд, **Таблица лута (N)**, *Тест*, *Сохранить*, *Отмена* |
| **Таблица лута** | записи с весом, подсчитанным шансом в % и числом команд; *+ Добавить*, *Тест*, *Изменить*, ✖ |

Списки (награды, команды, пороги, цели, лут) сохраняются в файл сразу после **Сохранить** в редакторе; *Общие настройки*
и *Донаты* — по своей кнопке **Сохранить**. Конфиг, изменённый на экране, не нужно перечитывать командой `reload`.
Если файл правился руками, пока экран открыт, нажми *Перечитать конфиг* перед редактированием, иначе экран перезапишет файл своей копией.

## 29. Файлы мода

Все пути — относительно папки игры (`.minecraft`).

| Файл | Содержимое |
|---|---|
| `config/twitchcraft.json` | весь конфиг (`configVersion: 11`). Создаётся с примерами при первом запуске; старые версии дополняются автоматически, а прежний файл сохраняется рядом как `twitchcraft.json.bak-v<старая версия>` |
| `config/twitchcraft-tokens.json` | токены Twitch (**секрет** — никому не показывать, не стримить папку `config`) |
| `config/twitchcraft-donations.json` | токен DonationAlerts, API-ключ DonatePay, последние обработанные донаты (**секрет**) |
| `config/twitchcraft-vk.json` | секрет приложения VK Video Live, токены и профиль (**секрет**) |
| `config/twitchcraft-youtube.json` | access/refresh tokens, OAuth scopes, профиль YouTube и счётчик дневной квоты Data API (день + единицы; не стирается при `logout`) (**секрет**); OAuth Client ID находится в основном конфиге |
| `config/twitchcraft-goals.json` | прогресс целей и время последнего запуска |
| `config/twitchcraft-fundraisers.json` | прогресс сборов средств: собрано, число вкладов, последний вклад, сколько раз закрыт (не сбрасывается сам) |
| `config/twitchcraft-stats.json` | счётчики событий игры за всё время: смерти, достижения, боссы, число сеансов, последняя смерть (`gameEventsSettings.persistStats`) |
| `config/twitchcraft-artifacts.json` | настройки аддона «Артефакты» (создаётся при первом запуске с аддоном): лимит артефактов, шансы редкостей, правила выдачи, награды по id (`drops.rewardIds`), тексты и расписание **боссов** (`bosses`: интервал, радиус, шансы навыков, шаблон вызова, тексты объявлений) |
| `config/twitchcraft-artifacts-state.json` | состояние аддона «Артефакты»: артефакты, проклятия, счётчики и **боссы** (кто появился, когда следующий, сколько побед и вызовов) — пишется атомарно; сломанный файл уходит в `.broken` |
| `logs/twitchcraft-events.log` (`.1`) | журнал событий |
| `logs/latest.log` | общий лог игры; строки мода помечены `[TwitchCraft]` — сюда смотреть при проблемах |

Файлы пишутся атомарно (через временный файл) — выключение света посреди записи не испортит конфиг. Если JSON всё же сломан
(например, после ручной правки), мод не затирает его, а переименовывает в `twitchcraft.json.broken-<дата>` и работает с
настройками по умолчанию, сообщая об этом в `/twitch status` и `/twitch reload`.

Ручная правка: любой текстовый редактор (Блокнот, VS Code). Обязательно сохранять в UTF-8. После правки — `/twitch reload`.
Неизвестные поля не ломают конфиг — о них будет предупреждение. Числа вне допустимых диапазонов приводятся к границам.

## 30. Безопасность

- **Команды от зрителей никогда не выполняются напрямую.** Зритель может только вызвать заранее настроенное действие;
  его текст попадает лишь в плейсхолдеры, которые очищаются (кавычки, переводы строк, управляющие символы, `§`) и подставляются один раз.
- **Чёрный список команд** `blockedCommands` (по умолчанию `stop op deop ban ban-ip pardon pardon-ip kick whitelist save-off save-on
  publish debug reload perf jfr transfer`) проверяется по словам, включая вложенные вызовы (`execute … run stop` тоже заблокирован).
  Заблокированная команда не выполняется, в лог пишется предупреждение. Можно расширять.
- **Права Twitch** запрашиваются минимальные: читать награды, подписки, битсы, фолловеров; читать/писать чат; управлять наградами.
  Мод не может банить, менять настройки канала, читать личные данные. Токены лежат только у тебя; `/twitch logout` отзывает их.
- **Client ID не секрет**; OAuth Desktop Client Secret для YouTube мод не просит и не хранит; **API-ключ DonatePay и access/refresh tokens — секреты**.
- **Вход в DonationAlerts**: приёмник на `localhost` работает ≤ 10 минут, проверяет одноразовый `state`, отвергает запросы с чужих сайтов,
  принимает токен один раз и выключается.
- **VK Video Live**: секрет приложения и токены — в отдельном файле `twitchcraft-vk.json` (права `rw-------` там, где ОС это умеет);
  приёмник кода работает ≤ 10 минут, проверяет `state`, принимает код один раз; права приложения — только чат, баллы и награды.
- **YouTube Live**: в основном конфиге только публичный OAuth Client ID; access/refresh tokens — в отдельном `twitchcraft-youtube.json`.
  Вход Desktop использует PKCE + одноразовый `state`; локальный callback принимает только соответствующий redirect во время активного входа.
- Ссылки из чата Twitch в игре некликабельны; цвета ников нормализуются; тексты ограничены по длине.
- Чат-команды из общего чата (Shared Chat) по умолчанию отключены.
- Повторы ограничены `maxRepeat`, очередь — `maxQueuedEvents`, темп — `maxEventsPerMinute` и `queueDelayTicks`, цели — 5 срабатываний за событие,
  ответы в чат — 20 за 30 с. Один «богатый» зритель не положит игру.
- Что **не** показывать на стриме: папку `config`, экран входа DonatePay с ключом, `/twitch status` показывает только имя аккаунта и срок токена — его показывать можно.

## 31. Игра на сервере

Мод клиентский и серверу не виден, поэтому на любом сервере работают: подключения к Twitch/VK/YouTube и сервисам донатов,
чаты в игре, оверлей, заголовки, тосты, звуки, ответы в чаты площадок-источников, статистика и цели.

Команды Minecraft из действий на чужом сервере отправляются **как обычные команды от твоего имени** (`player.connection.sendCommand`):

- нужны соответствующие права (OP) на сервере, иначе команды молча не сработают;
- `showCommandOutput` там не действует — ответы сервера видны как обычно;
- на серверах с плагинами синтаксис может отличаться; `delay` остаётся локальной паузой мода;
- `/twitch status` показывает `Режим: сервер`.

Если команды не нужны, а нужны только показ и статистика — всё работает без прав.

| YouTube: «дневная квота Data API исчерпана», чат остановился | Так работает `youtube.quotaGuard`: мод перестал тратить единицы и ждёт сброса Google (полночь по тихоокеанскому времени США; время показано в `/twitch youtube info`). | YouTube: `ban`/`delete` отвечает «подходит нескольким зрителям» или «зритель не найден» | Мод берёт `channelId` из реестра участников текущего чата (300 последних, запись живёт 6 часов). Передай точный `channelId` (`UC…`) вместо ника; до начала опроса чата реестр пуст. Забанить владельца или модератора YouTube не разрешает (`liveChatBanInsertionNotAllowed`) |
| `Конфиг не прочитан` | синтаксическая ошибка JSON (лишняя запятая, кавычки). Открой `twitchcraft.json.broken-…`, исправь, верни имя, `/twitch reload`. Онлайн-проверка: jsonlint.com |
| Экран настроек не открывается из Mod Menu | Mod Menu не для 26.3 или не установлен; `/twitch config` работает без него |
| Игра крашнулась | найди `crash-reports/crash-<дата>.txt`, строки с `twitchcraft` — пришли их разработчику вместе с `logs/latest.log` |

## 33. FAQ

**Нужен ли статус аффилиата?** Для баллов канала, подписок и битсов — да (их просто нет у обычных каналов). Фолловы, рейды, чат,
чат-команды, донаты, цели по фолловам работают у всех. Выключи ненужные модули, чтобы не видеть предупреждений о подписках.

**Можно ли настроить всё без JSON?** Да, весь конфиг доступен на экране настроек. JSON удобнее для массовых правок и бэкапов.

**Как сделать временный эффект с откатом?** Командами с паузой:
`["gamemode adventure", "delay 600", "gamemode survival"]` или `["time set midnight", "weather thunder", "delay 1200", "time set day", "weather clear"]`.
Для зелий проще указать длительность: `effect give @s minecraft:slowness 30 2`.

**Как сделать награду, где зритель пишет текст?** `"input": true` в награде + `{message}` в сообщении/заголовке — пример «Сообщение» в конфиге по умолчанию.
Текст очищается от опасных символов, но не от грубостей — модерируй награду на Twitch.

**Как выдать разные подарки по уровню подписки?** Разделами `subscribeByTier` / `resubByTier` / `giftSubByTier`
в конфиге или экраном *События Twitch* → **Уровни (N)**: ключ — уровень (`1`, `2`, `3`, `prime`), значение — своё действие.
Оно выполняется вместо базового (для ресаба и подарков — когда ни один порог по количеству не подошёл).
Если своё нужно только в тексте — плейсхолдер `{tier}` подставит уровень.

**Как сделать команду только для модераторов?** `"permission": "moderator"`.

**Как показать сбор «на микрофон» как полоску босса?** Он уже есть: `/twitch fund title Сбор &6Сбор на микрофон`,
`/twitch fund target Сбор 15000` — или то же на экране **Сборы средств (боссбар)**. Донаты заполняют полосу сами; битсы и подписки —
если задать им «курс» (`bitsRate`, `subValue`). Деньги мимо сервисов — `/twitch fund add Сбор 500 Вася`. Раздел 21а.

**Полоса сбора перекрывает полоску дракона/визера.** В настройках сборов поставь отступ сверху 31 (или больше, если боссов несколько) —
ванильные полосы идут с 12 px шагом 19. Или спрячь сбор на время боя: `/twitch fund hide Сбор`.

**Как отключить всё одной кнопкой?** `F8` (пауза), `/twitch disconnect` (отключиться до `connect`) или выключить модули группы «События».

**Можно ли несколько каналов / смотреть чужой канал?** Нет: мод работает с каналом того аккаунта, который подтвердил код входа.

**Как сменить аккаунт?** `/twitch logout` → `/twitch login` под другим аккаунтом.

**Куда делась статистика после перезапуска?** Статистика — на сессию; долговременная история — в `logs/twitchcraft-events.log`. Цели и сборы средств сохраняются.

**Безопасно ли давать моду права OP на сервере друзей?** Мод выполняет только команды из твоего конфига, но любой, кто может
активировать награду, запускает эти команды от твоего имени. Держи `blockedCommands` и не делай награды с `gamemode`, `op`, `stop` и т.п.

**Как перенести настройки на другой компьютер?** Скопируй `config/twitchcraft.json`; чтобы не входить заново, перенеси нужные секретные файлы:
`twitchcraft-tokens.json`, `twitchcraft-donations.json`, `twitchcraft-vk.json` и/или `twitchcraft-youtube.json`. Токены привязаны к Client ID; не отправляй эти файлы и храни их как пароли.

**Мод ничего не отправляет «наружу», кроме Twitch и сервисов донатов?** Да: только `id.twitch.tv`, `api.twitch.tv`, `eventsub.wss.twitch.tv`,
`www.donationalerts.com`, `centrifugo.donationalerts.com`, `donatepay.ru`. Никакой телеметрии.

| `&2` | тёмно-зелёный | `&a` | зелёный | `&n` | подчёркнутый |
| `&3` | тёмно-бирюзовый | `&b` | бирюзовый | `&m` | ~~зачёркнутый~~ |
| `&4` | тёмно-красный | `&c` | красный | `&k` | «шифр» (мерцающие символы) |
| `&5` | фиолетовый | `&d` | розовый | `&r` | сброс |
| `&6` | золотой | `&e` | жёлтый | | |
| `&7` | серый | `&f` | белый | | |

Пример: `"&6&l{user} &r&7задонатил &a{sum}&7!"`. В командах Minecraft (`tellraw`, `title`) `&` не обрабатывается — там свой JSON-формат.

## Приложение Б. Полезные команды для эффектов

Все команды выполняются от твоего имени: `@s` — ты, `~ ~ ~` — твоя позиция. Минус-эффекты лучше делать с кулдауном.

```
# Мобы
summon minecraft:zombie ~2 ~ ~2
summon minecraft:creeper ~ ~ ~3 {Fuse:60}
summon minecraft:creeper ~ ~ ~3 {powered:1b}                  # заряженный крипер
summon minecraft:skeleton ~-3 ~ ~
summon minecraft:zombie ~2 ~ ~2 {CustomName:'"{user}"',CustomNameVisible:1b}   # зомби с ником зрителя
summon minecraft:lightning_bolt ~ ~ ~
summon minecraft:tnt ~ ~ ~2
summon minecraft:chicken ~ ~1 ~ {Passengers:[{id:"minecraft:zombie",IsBaby:1b}]}  # зомби-наездник
summon minecraft:firework_rocket ~ ~ ~ {LifeTime:20}

# Предметы и опыт
give @s minecraft:diamond 1
give @s minecraft:cooked_beef 8
give @s minecraft:enchanted_golden_apple 1
give @s minecraft:elytra 1
xp add @s 100 points
xp add @s 5 levels
clear @s minecraft:dirt                                       # забрать предмет

# Эффекты (команда, цель, эффект, секунды, сила-1, скрыть частицы)
effect give @s minecraft:regeneration 10 1 true
effect give @s minecraft:speed 60 1
effect give @s minecraft:jump_boost 30 2
effect give @s minecraft:levitation 5 0
effect give @s minecraft:slow_falling 30 0
effect give @s minecraft:blindness 10 0
effect give @s minecraft:hunger 30 2
effect give @s minecraft:nausea 15 0
effect give @s minecraft:glowing 60 0
effect clear @s

# Мир
time set day / time set midnight / time add 6000
weather clear / weather rain / weather thunder
difficulty hard
setblock ~ ~3 ~ minecraft:anvil
setblock ~ ~-1 ~ minecraft:lava                               # осторожно!
fill ~-1 ~ ~-1 ~1 ~2 ~1 minecraft:glass hollow                # стеклянная клетка
spreadplayers ~ ~ 5 20 false @s                               # телепорт в случайную точку рядом
tp @s ~ ~20 ~
kill @e[type=minecraft:item,distance=..10]                    # убрать предметы вокруг

# Текст и звук, видимые/слышимые в мире (а не только тебе)
title @s title {"text":"ПРИВЕТ","color":"gold"}
tellraw @s {"text":"Сообщение в чат","color":"aqua"}
playsound minecraft:entity.ender_dragon.growl master @s ~ ~ ~ 1 1
particle minecraft:heart ~ ~2 ~ 1 1 1 0 20
particle minecraft:explosion ~ ~1 ~ 0 0 0 0 1

# Пауза внутри списка команд (только TwitchCraft)
delay 40                                                      # 2 секунды
```

Полный список команд: <https://minecraft.wiki/w/Commands>.
